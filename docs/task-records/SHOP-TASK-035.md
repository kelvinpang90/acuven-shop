- 密码哈希（`app/services/pw_hash.py`）：标准库 `hashlib.scrypt`，N = 2^14、r = 8、p = 5，每个密码 16 字节 `secrets` 随机盐，摘要 64 字节；哈希字符串为 `scrypt$n=16384,r=8,p=5$<盐>$<摘要>`（Base64url、不带填充，约 130 个字符，不超过 255）。`verify_password` 按字符串里的参数重新计算、以 `hmac.compare_digest` 比较；格式不合法（段数、算法名、参数不是 2 的幂或超出 N ≤ 2^16、r ≤ 16、p ≤ 16、盐不是 16 字节、摘要不是 64 字节、超过 255 个字符、不是字符串）、密码无法按 UTF-8 编码或计算失败时返回 False，不抛异常。`DUMMY_PASSWORD_HASH` 参数与真实哈希相同、盐与摘要为固定的全零字节，校验照样跑一次完整的 scrypt，并在比较后明确排除，对任何密码都不通过；docstring 写明用户名不存在时以它对齐密码校验耗时，账号存在时另写审计并提交多出的耗时差是 Kelvin 2026-10-05 接受的计时侧信道，不另做时序对齐。模块不写日志，`hash_password` 遇到无法编码的密码抛不带原文与异常链的 `ValueError`。docstring 写明之后的会员密码复用本模块；密码长度规则由调用方决定。
- 后台会话（`app/services/admin_auth.py`）：`issue_admin_session(db, admin_account_id, now)` 以 `secrets.token_urlsafe(32)`（43 个字符）为令牌，库里只存 SHA-256 十六进制摘要，到期为 now 加 30 天，不随使用延长；返回令牌、CSRF 令牌与会话记录（repr 不含令牌）。`check_admin_session(db, cookie_value, now)` 对格式不合法的值不查库；会话不存在、已撤销或到期时刻已到都返回空，通过时返回 `AdminSession`（`admin_account_id`、`expires_at` 可直接用，撤销当前会话时交给 `revoke_admin_session`，不必再查摘要）。`revoke_admin_session` 写撤销时间（已撤销的保留原时间），`revoke_all_admin_sessions` 以一条 UPDATE 撤销该账号全部尚未撤销的会话并返回条数。签发与撤销只 flush 不提交。时间一律不带时区的 UTC，带时区时抛 `ValueError`。
- CSRF：`csrf_token_for_cookie` = SHA-256(`acuven-shop/admin-session/csrf\0` + 令牌原文)，前缀不同于订单访问，不入库；`check_csrf_token` 以常量时间比较，令牌缺失、不一致或 cookie 缺失、格式不合法都不通过。后台写操作须同时通过会话校验与 CSRF 校验（由 SHOP-TASK-036 接线）。
- 审计：操作名常量 `admin_login_succeeded`、`admin_login_failed`、`admin_login_locked`、`admin_logout`、`admin_account_created`、`admin_password_reset`。`record_audit(db, action, admin_account_id, now, *, target_type, target_id, old_value, new_value)` 只 flush；操作名与对象类别须为小写字母开头的小写字母、数字与下划线且不超过列长，对象类别与 ID 须成对，否则抛 `ValueError` 不写库。本任务的操作都不带对象与旧值、新值；不存来源地址与提交的用户名。
- 登录锁定（同一文件，计数用 SHOP-TASK-026 的 `hit` 与 `current_count`，未改它们）：标识为 `json.dumps([来源, 规范化用户名])`，规范化即 `strip().lower()`，不用分隔符拼接（IPv6 来源含冒号）。`record_login_failure` 在失败计数桶 `admin_login_failures`（上限 9、窗口 3600 秒）计一次；计数超过上限（窗口内第 10 次及之后）时在锁定桶 `admin_login_lock`（上限 1、窗口 3600 秒，过期只在首次计入时设置）计一次，只有这次锁定桶计数未超过上限时返回「刚锁定」，并发的失败只有一个报刚锁定。`login_locked` 只读锁定桶，计数 ≥ 1 即锁定；锁定期间调用方即使密码正确也拒绝，锁定到期后照常校验密码。Redis 不可用时两者都抛 `RateLimitUnavailable`，调用方拒绝登录。docstring 写明按来源与用户名组合锁定的理由（攻击者无法把唯一的管理员锁在外面）与成功登录不清零失败计数，并写出给 SHOP-TASK-036 的建议顺序：已锁定即拒绝（不校验密码、不计失败）→ 按用户名找账号，不存在时以假哈希校验 → 失败则计数，账号存在时写 `admin_login_failed`、刚锁定时再写 `admin_login_locked`（用户名不存在的失败只计数不写审计）→ 成功则签发会话并写 `admin_login_succeeded`。
- 命令（`app/admin.py`，运营者在服务器上于 API 容器内运行，例如在本仓库检出的根目录里 `docker compose exec shop_api python -m app.admin create <用户名>`）：
  - `python -m app.admin create <用户名>`：用户名须为 3 到 32 个小写字母、数字或下划线（不规范化，不合即拒绝）；先在一个短会话里检查库里没有任何账号（有则拒绝、不读密码），再读密码，再在新会话里插入账号（创建与密码更新时间为当前 UTC）；插入撞上单例槽（或用户名）唯一约束时回滚，以同样的「already exists」拒绝；成功时写 `admin_account_created` 并提交。
  - `python -m app.admin reset-password`：库里没有账号时非零退出、不读密码；否则读密码，更新哈希与密码更新时间，撤销该账号全部后台会话，写 `admin_password_reset` 并提交，输出撤销的会话条数。
  - 两者都用 `getpass` 不回显地读两次密码，不一致、少于 12 或多于 256 个字符（按字符计）、输入中断时拒绝；没有密码的命令行参数，也不读环境变量。连接沿用 `SHOP_DATABASE_URL` 与 `app/db/session.py` 的会话工厂。退出码：成功 0，被拒绝或数据库出错 1，未配置数据库 2（argparse 参数错误为 2）。输出只有固定文字、用户名不回显、会话条数与数据库异常类名，不含密码、哈希或异常消息。
