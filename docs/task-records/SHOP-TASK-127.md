# SHOP-TASK-127 Stripe webhook 的事件解析与 Checkout 事件的同事务处理

- [x] 按 `docs/DESIGN.md` 1.12（提交 `acf576e`）「Stripe 测试环境支付」第 7 条（事件 ID 的去重记录与它引起的订单、积分或退款改动在同一个数据库事务里提交；已提交过的事件直接回 200；处理失败整个事务回滚；业务动作另按对象去重；只处理第 4、5 条的 Checkout 事件与 Stripe 退款状态事件，其他类型回 200 不处理；不存、不记录事件原文）、第 1 条（livemode 为真即拒绝）、第 3 条末句（本站没记下会话 ID 的会话按元数据里的创建幂等键与订单 ID 对上记录）、第 4 条（两个确认来源走同一个幂等处理）、第 5 条（complete 而付款未定时等 async_payment_succeeded，async_payment_failed 后按现有规则取消）与 `docs/HANDOFF.md` 0.55 的落实写法，新增事件解析（`app/services/stripe_gateway.py`）、`app/services/stripe_webhook.py`，并让 `confirm_checkout` 与 `cancel_after_stripe_end` 能把事件记录放进自己的提交；测试见 `tests/test_stripe_webhook.py`。设计闸门：DESIGN 1.12（提交 `acf576e`）与 HANDOFF 0.55，支付状态与取消。
- 事件解析：`app/services/stripe_gateway.py` 新增 `CHECKOUT_EVENT_TYPES`、`REFUND_EVENT_TYPES`、不可变的 `WebhookEvent`（id、type、livemode、session、refund）与 `parse_webhook_event(payload: bytes)`。不是 JSON 对象、object 不是 event、id 不是非空字符串或超过 `STRIPE_ID_MAX_LENGTH`、type 不是非空字符串或超过 `EVENT_TYPE_MAX_LENGTH`、livemode 不是布尔值、data.object 不是对象时返回 None；Checkout 事件以现有 `_parse_session`、退款事件以 `_parse_refund` 取对象，取不到整条为 None；其他类型（含 `checkout.session.expired`）两者都为空。livemode 为真照常返回，由接口拒绝。不抛异常、不写日志；现有函数未改。两个长度常量取自 `app/models/stripe.py`（只导入常量，适配器仍不读写数据库）。
- `record_event` 的提交时机：`confirm_checkout` 与 `cancel_after_stripe_end` 各加仅限关键字参数 `record_event`（入参数据库会话，默认 None，省略时行为不变）。给出时：`confirm_checkout` 在 `_write` 里 `_WRITES` 各步骤写入之后先 `db.flush()`、再在 `except IntegrityError` 之外调用 `record_event(db)`，然后提交；`cancel_after_stripe_end` 在返回 kept 与 cancelled 的两处提交之前先 flush、再调用。判定不需写入、返回 changed、回滚重来与轮数用完的路径都不调用。它抛出的异常原样传出、不重试，由调用方回滚。webhook 的回调写一条 processed 的事件记录并 flush，撞上事件 ID 唯一约束时抛 `EventAlreadyRecorded`（普通 Exception 子类）。两个模块说明各补一句。
- Checkout 事件的找回与分派（`handle_webhook_event(db, gateway, event, now)`）：now 带时区或 event.livemode 为真抛 ValueError，先于访问数据库。先结束当前事务，`_already_recorded` 普通读查到事件 ID 已有记录即 duplicate、不调用 Stripe。Checkout 事件先按会话 ID 找记录，找不到且元数据的创建幂等键非空、订单 ID 为十进制数字时按创建幂等键与订单 ID 找（含 creating 与 expired）；都找不到为 ignored、不调用 Stripe。找到后结束读事务，以事件会话 ID 查询一次，按查询到的会话分派（不看事件类型）：已付款经 `confirm_checkout`（传入查询到的会话与回调）；否则会话为 complete、ID 与创建幂等键都等于记录、会话 livemode 为假、PaymentIntent 的 livemode 不为真且状态属于 `stripe_overdue.FAILED_INTENT_STATUSES` 时以 system 调用 `cancel_after_stripe_end`（给记录 ID，seen_status 为查询前读到的状态，传回调）；否则 complete 经 `confirm_checkout` 只记下会话；open、expired 等不改。
- 结果映射：查询 unavailable 为 unavailable；live 记 `stripe_livemode`、rejected 记 `stripe_confirm_rejected`（只含记录 ID，沿用 `stripe_confirm.py` 的类别常量），都为 unavailable；这三种不留事件记录、订单与记录不变。`confirm_checkout` 返回 unavailable 为 unavailable，其余为 processed；`cancel_after_stripe_end` 返回 cancelled 或 kept 为 processed，changed 为 unavailable。回调未被调用而结果为 processed、以及 ignored 的情形，由 `_record_only` 在只写这一行的事务里写事件记录（处理时间为 now），撞上唯一约束回滚并返回 duplicate；捕获 `EventAlreadyRecorded` 时回滚并返回 duplicate。本模块除上述两类外不写日志，日志不含事件 ID 与事件或会话原文。
- 偏离与按验收标准未写死之处的取法（未改设计，未发现须停下的设计问题）：
  - 「订单 ID 为十进制数字」取 ASCII 的 `[0-9]`，并限 1 至 18 位：更长的取值超出整数列（SQLite 绑定时会溢出），按找不到（ignored）处理。
  - 事件类型属于 Checkout 而 `WebhookEvent.session` 为空（只可能由调用方直接构造，解析不会产生）时按其他类型记 ignored。
  - 回调是否「被调用」以本次处理里回调被调用过为准；回调在 flush 之后、提交之前调用，提交本身不再撞约束，所以不另查库核对事件记录是否已提交。
  - 已付款而会话不是 complete、身份核对不符等由 `confirm_checkout` 判为 unavailable 的情形，按结果映射为 unavailable、不留事件记录，由 Stripe 重发。
- 测试：`tests/test_stripe_webhook.py`（SQLite 内存库与 `FakeStripeGateway`，订单与会话记录的准备照 `tests/test_stripe_overdue.py` 在本文件里另写）覆盖解析的三类合格事件与各种不合格输入；completed 且已付款进入 demo_paid、事件记录为 processed；同一事件再来为 duplicate 且不调用 Stripe；creating 与 expired 记录按创建幂等键与订单 ID 找回并确认；找不到记录、`checkout.session.expired` 与其他类型为 ignored 且不调用 Stripe；async_payment_failed 而 PaymentIntent 为 canceled 时记录 expired、订单取消；complete 而付款未定只记下会话；事件类型与查询结果不一致时按查询结果（两个方向）；Stripe 不可用、查询为 live 与 rejected 时为 unavailable、没有事件记录、订单与会话记录不变并各记对应日志；把 `_already_recorded` 替换为恒返回假并预先插入同一事件 ID 时（确认与取消两路）返回 duplicate、订单与记录都未改；给 `confirm_checkout` 与 `cancel_after_stripe_end` 传入抛异常的回调时订单与记录都不变；不写入的路径不调用回调；livemode 为真与带时区的 now 抛 ValueError。每条测试的文档字符串写明守住的设计原句。未测退款事件类型。`tests/test_stripe_confirm.py`、`tests/test_stripe_cancel.py`、`tests/test_stripe_late_payment.py`、`tests/test_stripe_overdue.py`、`tests/test_stripe_gateway.py` 未改。
