# SHOP-TASK-089 会员计价与下单的接口

- [x] 按 `docs/DESIGN.md` 1.11（提交 `2d13250`）「计价、优惠、积分与库存」第 1 条（优惠券先抵商品额、积分再抵剩余商品额，二者均不抵运费）、「失败、并发与重试」第 1 条（幂等键；相同键相同请求返回原结果，同键不同内容报冲突）、「权限与资料保护」第 1、2 条（已登录会员结账不再验证；收货电话默认为会员手机号、可改为其他号码或虚构号码；会员改填的收货电话以收货国家作为默认区号解析，明确输入加号国家码时以该号码为准，只检查格式）与 `docs/UX.md` 0.10 P05（会员表单：优惠券代码与使用积分，摘要显示券与积分两行），以及 `docs/HANDOFF.md` 0.47 记录的 Kelvin 2026-10-11 决定（下单时券或积分已不可用即整单拒绝），在 SHOP-TASK-088 的 `quote_member_cart` 与 `place_member_order` 之上新建 `app/api/member_orders.py`（`app/main.py` 挂上路由），提供 `POST /api/member/checkout/quote` 与 `POST /api/member/orders`；测试见 `tests/test_member_orders_api.py`。不做前端，未改 `app/services/`、`app/api/orders.py`、`app/api/checkout.py`、`app/api/member_auth.py`、`.platform/`、CI、部署配置与设计，未加表或迁移，未装依赖。设计闸门：DESIGN 1.11（提交 `2d13250`）与 HANDOFF 0.46、0.47（优惠券与积分）。拆分：接口层（4 个允许路径）。
- 接口：路由器 `prefix="/api/member"`，用 SHOP-TASK-027 的 `_NoStoreRoute`，两个接口的处理函数与依赖产生的全部响应（含 413、415、422、429、401、403、409、503 与 `get_session` 的 503）都带 `Cache-Control: no-store`；路径存在但方法不匹配的 405 由框架在路由之外回答，不在此列。会员会话经 `app/api/member_auth.py` 的 `MemberDep`（`require_member`）与 `require_member_csrf`，422 沿用 `app/api/pay.py` 的 `_body_errors`，请求体读取沿用 `app/api/pay.py` 的 `_json_body`（8 KB），幂等键与目的地组合的校验沿用 `app/api/orders.py` 的 `_key_errors` 与 `_destination_errors`，收货资料的字段类型沿用 `RecipientName` 等。本模块不写日志（`enforce_source_limit` 在 Redis 出错时那一条只含桶名的警告除外）；响应与错误不含收货资料、券代码原文、幂等键、令牌或 cookie 值。
- 检查顺序（两个接口相同，每一步不通过即停止）：请求体逐块读，超过 8 KB 即 413，先于一切 → 读完不是 JSON 即 415 → 按访客来源限流（计价与 `POST /api/checkout/quote` 共用桶 `checkout_quote_source` 及其上限 10 分钟 300 次，下单与 `POST /api/orders/guest` 共用桶 `guest_order_source` 及其上限 1 小时 60 次，常量都从原模块引用；超过 429 `rate_limited`；Redis 未配置或出错时放行，照 `enforce_source_limit`）→ `require_member`（401 `member_session_required`）→ 只有下单：`require_member_csrf`（403 `csrf_failed`）→ 之后才校验请求体与 `Idempotency-Key`（规则同游客下单），多出字段 422，每条错误只给位置、类型与固定消息。前三步写在请求体依赖里，排在会员依赖之前；CSRF 与请求体校验在处理函数里依次调用。计价的 `lang` 查询参数同计价接口（`en`、`zh`、`ms`，默认 `en`），经 `app/api/pay.py` 的 `LanguageDep`（`_language`）在会话依赖之后判断，不合法时 422 只有一条 `{"type":"literal_error","loc":["query","lang"],"msg":"Input should be 'en', 'zh' or 'ms'"}`，不回显所给的值。
- 计价的请求体：`lines`、`country_code`、`state_code` 照 `app/api/checkout.py` 的 `QuoteRequest`（子类继承其严格类型、禁止多出字段与 SKU 不重复、州属须有国家的校验），另加可省略的 `coupon_code`（1 到 64 个字符的字符串，可为 null）与 `points`（0 到 100000000 的严格整数，默认 0）。响应为计价接口的全部字段（`lines`、`subtotal_sen`、`shipping`、`total_sen`、`fx_reference`、`can_place_order`），另加 `coupon_applied`（未给代码或有不正常的行时为 null，否则为布尔）、`coupon_discount_sen`、`points_available`、`points_max`（可用余额与券后商品额的较小值）、`points_accepted`、`points_redeemed` 与 `points_earned`；`total_sen` 与 `fx_reference` 取 `quote_member_cart` 的结果，即扣除券与积分之后的合计及其参考外币，未给收货国家时为 null。无效目的地 422 `invalid country or state code`、运费缺失 503 `shipping is unavailable`（同计价接口）；`MemberNotActive` 401 `member_session_required`；`SQLAlchemyError` 回滚后 503 `service_unavailable`。
- 下单的请求体：`lines`、`name`、`address`、`postal_code`、`country_code`、`state_code`、`region` 的规则同 `POST /api/orders/guest`（`lines` 与计价接口相同，1 到 20 行、每行 1 到 99 件、SKU 不重复；重复 SKU 由 `_destination_errors` 报 422 `{"type":"value_error","loc":["body","lines"],"msg":"each SKU may appear only once"}`，不进入下单函数），必填的收货电话 `phone`（严格字符串），可省略的 `coupon_code` 与 `points`（规则同计价）；不收 `phone_region`（多出即 422）。收货电话以收货国家为默认地区经 `normalize_phone` 规范化（以加号开头时以输入为准）；收货国家不在 `phonenumbers.SUPPORTED_REGIONS` 里时，以加号开头的输入以 `MY` 作默认地区调用（此时默认地区不参与解析），否则不成立；不成立 422 一条 `{"type":"phone_invalid","loc":["body","phone"],"msg":"invalid phone number"}`。规范化结果作为 `MemberOrderRequest.phone` 写入收货资料并计入请求指纹。不读短信验证开关，不按白名单拒绝。
- 下单的结果：调用 `place_member_order`，新订单 201、重放 200，响应只有 `order_number`、`status`、`subtotal_sen`、`coupon_discount_sen`、`points_redeemed`、`shipping_fee_sen`、`total_sen`、`points_earned` 与 `payment_expires_at`（带 UTC 时区），不含收货资料与令牌，不设置任何 cookie。`MemberNotActive` 401 `member_session_required`；409 的 `detail` 为 `idempotency_conflict`、`order_not_placeable`、`coupon_invalid`（`CouponUnavailable`，页面的 `checkout.coupon_invalid`）与 `points_unavailable`（`PointsUnavailable`）；无效目的地 422、运费缺失 503（同计价）；`SQLAlchemyError` 回滚后 503 `service_unavailable`。
- 偏离与取舍，请审阅（未改设计，未发现须停下的设计问题）：
  - 券代码不去空白、不把空白当作省略（SHOP-TASK-088 记录把这一点留给本任务）：给了 1 到 64 个字符的字符串即视为给了代码，全空白的代码在计价时 `coupon_applied` 为 false、下单时 409 `coupon_invalid`；前端在输入框为空时应省略该字段。`coupon_code` 显式为 null 与省略相同。
  - 两个接口都先查 415 再限流（游客下单是这个顺序；游客计价接口不查 415，读完即限流），与验收写的检查顺序一致。
  - 计价接口在验收列出的字段之外不另给券或积分的原因；`can_place_order` 照 SHOP-TASK-088 沿用 `quote_cart`，券不可用或积分不被接受时仍可为真，由下单时整单拒绝把关。
  - 下单数据库出错时 `place_member_order` 已先回滚；处理函数仍照 `app/api/member_auth.py` 的 `_rollback` 再回滚一次（回滚本身出错也吞掉）。
  - `require_member` 已拒绝不是 active 的会员，`MemberNotActive` 只在会话检查之后、下单锁会员行之前会员被注销时出现；测试以注销后的会话验证两个接口都是 401。
- 留给之后的任务：前端会员表单（P05 第 3 步的会员表单：收货电话预填会员手机号、优惠券代码与使用积分输入、摘要的券与积分两行、`checkout.coupon_invalid` 等提示，以及 V1 短信验证后以会员身份继续）留给之后的前端任务（规划块「已阻塞」里的「短信验证组件 V1 与结账会员路径」）；会员订单的支付、取消与超时接入券与积分留给 SHOP-TASK-090；支付页与结果页的会员接口留给 SHOP-TASK-091。
- 验证到什么程度：人工逐条对照验收标准、DESIGN 1.11 原句、UX 0.10 P05 与 HANDOFF 0.47 的 Kelvin 决定自查。`tests/test_member_orders_api.py` 用 `TestClient`（`https://testserver`）与 SQLite 内存库（引擎设置同 `tests/test_guest_order.py`），会话依赖换成绑定同一内存库的会话（可换成提交即抛错的子类）；会员会话经 `issue_member_session` 签发并提交，cookie 与 CSRF 令牌放进请求头（写法同 `tests/test_member_pw_api.py`）；积分经 `earn_points` 发放，用满的券经另一会员的 `reserve_coupon` 预占；结果都在另一个数据库会话里读；限流用可选 Redis 依赖的内存替身；未加依赖。每条测试的文档字符串写明它守住的设计、UX、Kelvin 决定或验收条目。覆盖：两个接口超过 8 KB 为 413（不是 JSON、没有会话也是）、不是 JSON 为 415（没有会话也是）、恰好 8 KB 且没有会话为 401；限流按来源计入与游客接口相同的桶，达到上限后 429 先于 401；下单缺少或错误的 CSRF 为 403 且不写库，计价不要 CSRF；两个接口多出字段（含 `phone_region`）422 且错误只有位置、类型与消息、不回显；计价的券代码与积分字段规则；计价不合法的 `lang` 422 且不回显；下单重复 SKU 422 且不写库；缺少或不合的幂等键 422；计价给出券与积分两行与扣除后的合计且不写库，券过期时 `coupon_applied` 为 false 且不计入，未给代码为 null、积分默认 0，积分超过余额不接受，参考外币按扣除后的合计换算，未给收货国家时合计为 null 而券与积分照样判定，无效目的地 422、运费缺失 503；下单 201 的字段、金额、带 UTC 时区的到期时间、不设 cookie 与不回显，库存、用券记录各增一次，收货电话为规范化结果，重放 200 且不再改库；同一号码换写法重放 200、另一号码 409；同键不同积分 409；券被用满 409 `coupon_invalid` 且库存与各表不变；积分超过余额 409 `points_unavailable` 且不变；超出限购 409 `order_not_placeable`；运费缺失 503；提交失败 503 `service_unavailable` 且全部回滚；收货电话按收货国家解析（MY、SG）、以加号开头时以输入为准、收货国家不受 phonenumbers 支持时须以加号开头、5 种格式不成立为 422 `phone_invalid` 且不回显；短信验证开关开启时马新号码的会员照常下单；会员注销后两个接口都 401；无 `app.` 日志，日志不含收货资料、券代码、幂等键与令牌。未连真实 Redis 或 MySQL，并发下单（会员行锁）未在真 MySQL 上验证，未在真实浏览器里验证。这些测试只由 PR 的必需 CI 检查 backend 执行，Worker 沙箱不跑 pytest。检查命令结果由 Worker 另行记录。
