- [x] 页面（`frontend/src/pages/AdminProductsPage.tsx`，写法照 SHOP-TASK-203、204）：
  - 状态：新增的值与 SKU 放在 `ProductForm` 已有的数组末尾（203 记录里留给 205 的位置），不另加字段，`formOf` 与 `editorOf` 的形状不变。`OptionForm.values` 为已有的 `ValueForm`（id）或新增的 `NewValueForm`（`tempId` 与三语名称）；`ProductForm.variants` 为已有的 `VariantForm`（id）或新增的 `NewVariantForm`（`tempId`、按规格名顺序的所选值 `choices`、价格与库存原文、启用）。`isNewValue`、`isNewVariant` 区分两种形状；`valueKey` 为下拉框与 `choices` 里的写法（已有的为 ID 的十进制，新增的为临时编号）。
  - 临时编号：规格值为 `v1`、`v2`…（跨全部规格名），SKU 为 `s1`、`s2`…，取同一种新增里已用的最大数字加一，所以按新增顺序递增，去掉之后再新增也不会与请求里的重复。
  - 导出的纯函数：`addValue`（在该规格名的值之后加一个三语名称为空串的值，达 20 个不变）、`removeValue`（只去掉未被新增 SKU 选用的新增值）、`addSku`（在全部 SKU 之后加一行：每个规格名选空选项、价格与库存为空串、默认启用；没有规格名或达 50 个不变）、`removeSku`（只去掉新增 SKU）、`chooseValue`（只改新增 SKU 的所选值）；`canAddValue`、`showsAddSku`、`canAddSku`、`valueRemovable`；`valueChoices`（空选项在前，其余为该规格名下已有的与新增的值，文字为已填的名称，按后台界面语言、缺译回退英文，都为空时为空文字）与 `newSkuRows`；`MAX_VALUES` = 20、`MAX_VARIANTS` = 50。增删与改选都经 `withForm`，像其他输入一样收起保存结果。203 的价格、库存与启用的改动函数对新增 SKU 同样适用。
  - 页面先查与请求体：`saveInput` 的已有行照旧；新增的值写成 `temp_id` 与三语名称，排在该规格名已有的值之后；新增 SKU 写成 `temp_id`、按规格名顺序的 `option_values`（已有的值以 `{ id }`、新增的值以 `{ temp_id }` 引用）、价格整仙、每日初始库存与启用，排在已有 SKU 之后。新增 SKU 的价格、库存格式或范围不对，或任一规格名未选值时为 null（`submitProduct` 照 204 不发请求、显示 `admin.product_invalid`）；`publishReady` 原本就遍历全部值与 SKU，新增值的英文名称（上架时）与新增 SKU 的启用随之计入。新增值英文名称是否重复、组合是否重复不在页面判断。
  - 未保存的修改：`isDirty` 改为按形状逐项比较（`sameValue`、`sameRow`）；基线取自读取的商品，没有新增行，所以有任一新增的值或 SKU 时个数不同、即为有修改，加了又去掉不算。保存成功、`admin.reload` 与切换商品都经 `editorOf` 换成读取或返回的商品，新增行随之丢弃或变为已有行。
  - View：规格区每个新增值为输入框（读屏标签 `admin.option_value`，随内容语言）与其右的 (✗)（`valueRemovable` 为假时禁用）；每个规格名的值之后为次要按钮 `admin.add_value`（达 20 个禁用）。桌面 SKU 表格末尾为新增行：`admin.sku_code_on_save`、每个规格名一个下拉框（读屏标签 `admin.option_value`）、价格与每日初始库存输入框、启用勾选框、当日可用库存 — 与 (✗)；有新增行时表格多一列（列头为空，已有行该格为空）放 (✗)；表格之下为 `admin.add_sku`。手机卡片之后为新增 SKU 卡片：第一行为 `admin.sku_code_on_save` 与 (✗)，其下为下拉框、价格与库存、启用与当日可用库存 —；卡片之下为 `admin.add_sku`。`admin.add_sku` 在没有规格名的商品上不渲染、达 50 个禁用。已有 SKU 与已有值的写法未改（只把共用的价格、库存与启用输入抽成 `SkuCells` 与 `CardInputs`）。
  - 容器：`AdminProductsViewProps` 另有 `onAddValue`、`onRemoveValue`、`onAddSku`、`onRemoveSku` 与 `onChooseValue`，各只调用对应的纯函数改编辑区；传给事件属性的处理函数都不返回 Promise。
