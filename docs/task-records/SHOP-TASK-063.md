- 请求：`readAdminStoreDesign(language, signal?)` 以 `GET /api/admin/store-design?lang=<语言>` 读取（没有请求体、不带 CSRF 头）；`saveAdminStoreDesign(input, csrfToken, language, signal?)` 以 `PUT /api/admin/store-design?lang=<语言>` 保存，请求头 `X-CSRF-Token` 为调用方给出的 `csrf_token`（沿用 `api/pay.ts` 的 `CSRF_HEADER`）、`Content-Type: application/json`，JSON 请求体只按顺序放 `theme`、`accent`、`home_blocks`（每项只取 `block` 与 `visible`）与 `featured_product_ids` 四个字段，调用方对象上多出的字段不进请求体，数组顺序原样保留（即位置）。两者都是同源 cookie、`cache: "no-store"`、`Accept: application/json`，`lang` 是唯一的查询参数（`adminStoreDesignUrl`）。
- 字段与归类：只取 SHOP-TASK-051 记录段列出的字段，多出的字段不带进结果。读取为 `theme`、`accent`、`home_blocks`、`featured`（每项 `product_id`、`slug`、`name` 或 `null`、`published`）、`choices`（每项 `product_id`、`slug`、`name`）与 `csrf_token`（类型 `AdminStoreDesignDetail`）；保存为 `theme`、`accent`、`home_blocks` 与 `featured`（类型 `AdminStoreDesign`，不要求也不带进 `choices` 与 `csrf_token`）。主题、主色与区块直接复用 `storeDesign.ts` 的 `parseStoreDesign`（主题在 `THEME_ACCENTS` 内、大小写不同也不算；主色为 `null` 或属于该主题；`home_blocks` 恰为 `HOME_BLOCKS` 的一个排列、`visible` 为布尔值），精选最多 `FEATURED_COUNT`（4）件；`featured` 与 `choices` 各自的 `product_id` 不重复且为正整数，`slug` 为非空字符串，精选的 `name` 为字符串或 `null`、`published` 为布尔值，`choices` 的 `name` 为字符串，`csrf_token` 为非空字符串；任一字段缺少或类型不对整份不合格。读取结果 `StoreDesignRead` 归为 `ok`、`none`（401）、`failed`（其他状态与 200 但响应体不是 JSON 或不合格）与 `network`；保存结果 `StoreDesignSave` 归为 `ok`、`none`（401）、`csrf`（403）、`failed`（422 的各错误码与结构错误、413、415 等其他状态，以及 200 但响应体不合格）与 `network`。调用方传入的 signal 原样交给 `fetch`；中止时与现有模块相同，`fetch` 抛错归为 `network`（若在读响应体时中止则为 `failed`），由页面按 signal 已中止不再更新。
- 偏离与取舍，请审阅（未改需求与设计）：
  - 保存的 422 不按错误码（`theme_invalid`、`accent_invalid`、`featured_unavailable`）细分，都归为 `failed`，与验收的归类一致；页面若要按错误码提示，需另改本模块。
  - 保存前不在前端校验请求（主题、主色、区块与精选由服务端校验，不合格得到 422 即 `failed`）；模块只保证请求体的形状。
  - 响应里的 `product_id` 只要求正整数（安全整数范围内），不另按服务端请求体的上限 2147483647 检查；`choices` 不限件数。
  - 保存的响应体里 `published` 为 `false` 的精选合格（SHOP-TASK-061：原已在精选里、之后下架的商品保存时放行）。
  - 结果对象的字段名沿用接口的 snake_case（`home_blocks`、`product_id`、`csrf_token`），与 `api/adminRefunds.ts` 相同；前台 `storeDesign.ts` 的 `StoreDesign` 用的 `homeBlocks` 只在复用校验时转换。
  - 读取也接受 `signal`，保存同样可传入（验收「调用方可传入 AbortSignal」），与 `api/adminRefunds.ts` 的审核请求不带 signal 不同。
