- 两个接口（前缀 `/api/admin/site-settings`，路由类 `_NoStoreRoute`，处理函数与依赖产生的全部响应含错误都带 `Cache-Control: no-store`；路径存在而方法不匹配的 405 由框架回答，不在此列），都经 `require_admin`（401 `admin_session_required`）：
  - `GET`：返回 `payment_method`（照 `get_payment_method`：simulated 或 stripe_test，缺行或不认识的值为 simulated）、`stripe_available` 与 `csrf_token`（照 `app/api/admin_store_design.py` 由 cookie 算出）。只读，不写审计，不返回短信验证开关。
  - `PUT`：照店铺装修的保存接口，检查顺序 413（逐块读，超过 8 KB）→ 415（不是 JSON）→ 401 → 403 `csrf_failed` → 422（请求体只有 `payment_method`，取 `simulated` 或 `stripe_test`，`extra="forbid"`、`strict=True`，含短信验证开关字段、未知值或大小写不同一律 422，错误沿用 `_body_errors`，只给位置、类型与固定消息，不回显）→ 值为 stripe_test 而凭据不可用时 422 `{"detail":"stripe_not_configured"}`、不写入（当前已是 stripe_test 也一样）；切回 simulated 不看配置。成功或与当前值相同都回 200 与保存后的 `{"payment_method": …}`。
- 凭据判定以 `app/services/stripe_gateway.py` 的 `stripe_configured(request.app.state.settings)` 为准（HANDOFF 0.54）：密钥以 `sk_test_` 或 `rk_test_` 开头、webhook 签名密钥以 `whsec_` 开头、API 地址与站点地址都是 `https://`、演示邮箱非空，五项都满足才可用——比设计第 2 条所写的「测试密钥与 webhook 签名密钥」两项更严。GET 与 PUT 都在当次请求里调用它，不缓存。接口不写日志；密钥非空而不是测试前缀时由 `stripe_configured` 记 SHOP-TASK-111 的 `stripe_key_not_test`（每进程一次），不在此列。
- 保存（`save_payment_method(db, admin_account_id, method, stripe_available, now) -> (保存后的值, 是否改动)`）照 `save_store_design` 在一个事务里完成：先判 stripe_test 而凭据不可用（抛 `PaymentMethodRejected("stripe_not_configured")`，不查库）；再回滚此前的事务，以 `lock_site_setting_statement()`（`SELECT … FOR UPDATE`，`populate_existing`）锁住 ID 为 1 的那一行，使锁定成为新事务的第一条语句；行不存在时在保存点里按默认值（短信验证关闭、支付方式模拟）插入，撞上主键即回滚保存点再锁定。当前值按 `get_payment_method` 的规则解读；与请求相同时回滚、不写入、不写审计；否则改支付方式与更新时间，经 `record_audit` 写一条 `admin_payment_method_changed`（对象类别 `site_setting`、对象 ID 为该行 ID、旧值与新值为 simulated 或 stripe_test，操作者为当前管理员）后一并提交。短信验证开关不动。模块说明里「只读、不写」一句改写为读取只发 SELECT、只有支付方式可以修改。
- 偏离与取舍，请审阅（未改设计，未发现须停下的设计问题）：
  - 库里是不认识的值（如 MySQL 默认排序规则下能通过检查约束的大写 `STRIPE_TEST`）时，保存按 `get_payment_method` 把它当 simulated：保存 simulated 视为相同、不改写那个值也不写审计；保存 stripe_test 写入并记旧值 simulated。这样审计的旧值与新值总是两个常量之一（验收），也与访客发起支付时实际生效的值一致。
  - 凭据检查放在锁定之前、不查库：配置是进程级的，与库里的当前值无关；验收要求「当前已是 stripe_test 也一样」被拒，所以不必先读当前值。
  - 两个响应模型命名为 `PaymentMethodOut` 与 `AdminSiteSettingsOut`，不用 `SiteSettingsOut`：公开接口 `app/api/site_settings.py` 已用这个名字，OpenAPI 的模型名会冲突。
  - `PUT` 的返回只有 `payment_method`（验收「回 200 与保存后的 payment_method」），不带 `stripe_available` 与 `csrf_token`；页面要最新的凭据状态时再 GET。
  - `app/models/site.py` 模块说明里「修改设置的接口与审计记录由之后的管理后台业务接口任务实现」一句已不准确，该文件不在本任务允许改动的路径内，未改，留给之后碰到它的任务顺手改写。
