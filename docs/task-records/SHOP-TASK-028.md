- 请求与重试规则：
  - 查单：输入框标 `required`，`canLookup` 只要求两项去掉首尾空白后非空、且没有进行中的查询，格式（大小写、连字符、空格、国家码）由服务端判定，输入原样放进请求体。`POST /api/orders/lookup`（同源 cookie 以接收查单授权，`cache: "no-store"`），请求体只有 `order_number`、`phone`；提交期间按钮禁用。204 时站内导航到 `/track/order`（不带订单号、电话或查询参数）；404 显示 `lookup.not_found`，429 显示 `common.rate_limited`，503 显示 `common.service_unavailable`，网络中断（fetch 抛错）显示 `common.network_check`，其他意外回答（含 204 以外的 2xx）显示 `common.error_retry`；都留在本页，输入框保留已输入的值。
  - 读取订单：P09 打开与切换语言时调用 `GET /api/orders/lookup?lang=<当前语言>`（同源 cookie、`cache: "no-store"`）。打开时取 `orders[0]`（最近查询的）；之后的每次重新读取（切换语言、确认收货之后）都按已显示的订单号取该单，列表里已没有该单时按授权过期整页提示。
  - 确认收货：按钮只在 `demo_shipped` 且没有操作进行中时可点。点击时 `POST /api/orders/confirm-receipt`，请求体只有 `order_number`，请求头 `Idempotency-Key` 每次点击由 `crypto.randomUUID()` 新生成、`X-CSRF-Token` 为最近一次读取时接口给的令牌；提交期间按钮禁用。200 或 409 `order_not_confirmable` 时重新读取该单并按新状态显示（确认收货卡片随之消失）；403 时重新读取该单取得新令牌，再显示 `common.error_retry`；401 时整页 `order.session_expired`（重新读取得到 401 时同样）；其他回答（含 200 以外的 2xx、409 `idempotency_conflict` 与 5xx）显示 `common.error_retry`。
  - 网络中断：显示 `common.network_check`，按钮保持禁用，重新读取该单（读取也中断或失败时每 5 秒再读，直到得到回答）；已不是 `demo_shipped` 时按新状态显示，401 整页过期；仍为 `demo_shipped` 时显示 `common.error_retry` 并允许重试，下一次点击沿用中断那次的幂等键，之后的任何其他回答都清除这个待重试的键。离开页面时中止进行中的读取与确认。
  - 订单号、电话与 CSRF 令牌只在 React 状态里，不写 localStorage、sessionStorage、cookie 或历史记录，不进任何路径或查询参数；三个接口的地址固定（GET 只带语言）。输入框不设 `name` 且关闭自动填充，不用脚本时表单（`method="post"`）也提交不出任何字段。页面不显示授权内容或其剩余时间。
  - 收货地址为马来西亚时另调用 `GET /api/checkout/regions`（不带 cookie）把州属代码换成名称，失败时显示代码；国家名称用 `Intl.DisplayNames` 按界面语言本地化（与 P06、P07 相同）。
