# SHOP-TASK-088 会员下单的计价与下单规则

- [x] 按 `docs/DESIGN.md` 1.11（提交 `2d13250`）「计价、优惠、积分与库存」第 1 至 3、6、8 条（优惠券先抵商品额、积分再抵剩余商品额，二者均不抵运费，最终应付不低于运费；券仅会员可用，券与积分在下单时预占；逐件分摊；15 分钟未支付自动取消；下单时重新校验限购）、「失败、并发与重试」第 1 条（幂等键；库存、券与积分预占及订单创建在同一事务，失败全部回滚）、「权限与资料保护」第 1、3 条（已登录会员结账不再验证；会员下单的订单创建时即标记为不可认领），以及 `docs/HANDOFF.md` 0.47 记录的 Kelvin 2026-10-11 决定（券或积分在下单时已不可用即整单拒绝；获得积分在下单时写快照、模拟支付成功时发放），在 SHOP-TASK-085、086 之上实现会员结账的计价与下单规则函数：`app/services/member_ordering.py`；测试见 `tests/test_member_ordering.py`。不做接口，不接入支付与取消；未改 `app/services/ordering.py`、`pricing.py`、`checkout.py`、`coupons.py`、`points.py`、模型、迁移与设计，未加表。设计闸门：DESIGN 1.11（提交 `2d13250`）与 HANDOFF 0.46、0.47（优惠券与积分）。
- 计价（`quote_member_cart(db, member_id, items, country_code, state_code, coupon_code, points_to_redeem, now, *, lang="en")`）：只读，不写库、不锁行。会员不存在或不是 active 抛 `MemberNotActive`；再按 `quote_cart` 计价（目的地不合法、运费行缺失照它抛出）。有不正常的行时不判定券与积分：券是否可用为空，券折扣、积分抵扣与获得积分为 0，积分上限为 0、不接受抵扣积分，可用余额照常给出，合计与参考外币即 `quote_cart` 的结果。所有行都正常时（不论是否给了收货国家）：券代码非空则经 `check_coupon`（内含 `normalize_coupon_code`）判定，只给是否可用、不给原因，不可用不计入；积分上限为 `available_points` 与券后商品额的较小值，抵扣积分不超过上限时计入，超过时不计入并标明不接受；券折扣、积分抵扣与获得积分取 `price_order` 的结果；给了收货国家时合计为现金实付合计加运费，参考外币按这个合计用 `reference_amount` 换算；其余字段（各行、商品小计、运费、可否下单）沿用 `quote_cart`。
- 下单（`place_member_order(db, member_id, request, idempotency_key, now)`，`request` 为 `MemberOrderRequest`）的步骤与锁顺序：
  1. 请求指纹（`member_request_fingerprint`）写法同 `request_fingerprint`（JSON 键排序、无空白、非 ASCII 转义后取 SHA-256），内容另含会员 ID、券代码（规范化成立时取规范化结果，不成立时取去掉首尾空白的原文，为空时为 null）与抵扣积分。先按幂等键查订单，有则重放或报冲突。
  2. 没有该键时先回滚此前的只读事务，使以 SELECT … FOR UPDATE（`populate_existing`）锁住该会员的行成为新事务的第一条语句（照 `app/services/refund_review.py` 的锁定协议，之后的读取都不早于这个锁，看得到等锁期间别人提交的预占），锁后核对为 active，否则 `MemberNotActive`。
  3. 按收货国家与州属以 `quote_cart` 重新计价；不可下单、运费缺失或行数不符抛 `OrderNotPlaceable`。按 SKU 规格 ID 从小到大扣库存（直接导入 `app/services/ordering.py` 的 `_reserve_stock`、`_order_items`、`_order_by_key` 与 `PAYMENT_WINDOW`），扣不到抛 `OrderNotPlaceable`。
  4. 券代码非空时经 `normalize_coupon_code` 与 `check_coupon` 判定，不成立或不可用抛 `CouponUnavailable`；抵扣积分大于 `available_points` 或券后商品额抛 `PointsUnavailable`；按 `price_order` 计价，券参数取自查券结果（`price_kwargs()`）。
  5. 同一事务里写订单（`member_id` 为该会员、`claim_status` 为 `not_claimable`，券折扣、积分抵扣、获得积分取 `price_order` 的结果，合计为现金实付合计加运费，支付到期时间为当前时间加 15 分钟）、订单行、逐件分摊、收货资料与一条操作者为 `member` 的下单事件；有券时调用 `reserve_coupon`（本单券折扣为 `price_order` 的券折扣合计），返回不通过即 `CouponUnavailable`；抵扣积分大于 0 时调用 `reserve_points`，`InsufficientPoints` 即 `PointsUnavailable`。不签发游客短期凭据。全部成功后提交，返回 `MemberOrderResult`（订单摘要：订单号、状态、商品小计、券折扣、积分抵扣、运费、合计、获得积分、支付到期时间；与是否新建）。
  - 加锁顺序：会员 → 库存（规格 ID 升序的条件更新）→ 订单（`reserve_coupon` 与 `reserve_points` 各自再锁会员与订单）→ 券 → 积分批次与流水；会员 → 订单 → 券与 SHOP-TASK-085、086 一致，游客下单只锁库存，不形成相反的顺序。行锁只在 MySQL 上成立：SQLite 不支持行锁，SQLAlchemy 在 SQLite 上不生成 FOR UPDATE。
- 拒绝条件与回滚：会员不是 active（`MemberNotActive`）；有不可购买、超出限购或库存不足的行、运费缺失或扣库存失败（`OrderNotPlaceable`，与游客下单同一个异常类）；券代码不成立、查券不可用或预占时在券行锁下重新判定不通过（`CouponUnavailable`）；抵扣积分超过可用余额或券后商品额、或预占时余额不足（`PointsUnavailable`）。目的地不合法与运费行缺失照 `quote_cart` 抛出。任何一步拒绝或失败（含插入订单撞上幂等键唯一约束与提交失败）都回滚整个事务（库存、订单、券与积分都不留下），再按幂等键查一次：同键的并发请求已提交则按重放处理，否则抛出原异常。本模块不写日志，异常不带消息（不含个人资料、订单号、券代码、幂等键或令牌）。
- 快照：订单与逐件分摊的券折扣、积分抵扣、现金实付与获得积分都取 `price_order` 的结果；各件的 `points_earned` 即逐件获得积分（Kelvin 2026-10-11 决定 3，下单时写快照），整单 `points_earned` 为其合计。下单时不发放积分（不写批次），由 SHOP-TASK-090 在模拟支付成功时按订单快照调用 `earn_points`。
- 重放：订单的 `member_id` 等于该会员且指纹相同时返回原订单的当前摘要与 `created=False`，不重新计价，不动库存、券与积分；否则抛 `IdempotencyConflict`（与游客下单同一个异常类），包括另一会员或游客订单用了同一键。
- 偏离：未改设计，未发现须停下的设计问题。说明几处取舍，请审阅：
  - 计价函数多一个仅限关键字的 `lang`（默认 `en`），传给 `quote_cart` 决定各行名称与规格的语言；验收列出的入参都在，顺序相同。下单时的计价同游客下单用 `en`（订单行另存三语快照）。
  - 券代码以「是否为 None」区分有没有给：空串或全空白视为给了代码，计价时为不可用、下单时抛 `CouponUnavailable`；空白输入转成 None 由接口任务（SHOP-TASK-089）决定。
  - 计价有不正常的行时 `points_accepted` 一律为假（即使抵扣积分为 0）；所有行都正常时抵扣积分为 0 视为接受。计价结果的 `can_place_order` 沿用 `quote_cart`，不因券不可用或积分不被接受而变；这两种情况由下单时整单拒绝把关。
  - 下单时的查券与可用余额是会员行锁之后的普通读，结果在券行锁（`reserve_coupon`）与积分批次锁（`reserve_points`）下再判定一次，以后者为准；前者只为在扣库存后、写订单前尽早拒绝。
  - 下单函数一开始就回滚会话里此前的事务，调用方不得在同一会话里留有未提交的写入。时间带时区抛 `ValueError`，抵扣积分不是 int（含 bool）抛 `TypeError`、负数抛 `ValueError`，都在访问数据库之前。
  - 重放不看订单状态与支付到期时间，返回订单当前的摘要。
- 留给之后的任务：会员下单与计价的接口、登录会话与 CSRF、请求格式校验与会员改填收货电话的规范化留给 SHOP-TASK-089；模拟支付成功时核销券（`use_coupon`）与按快照发放积分（`earn_points`）、取消与支付超时时释放券（`release_coupon`）与积分（`release_points`）及库存的接线留给 SHOP-TASK-090。
