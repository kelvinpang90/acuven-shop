# SHOP-TASK-121 会员支付页的 Stripe 发起与确认接口

- [x] 按 `docs/DESIGN.md` 1.12（提交 `acf576e`）「Stripe 测试环境支付」第 3、4、9 条（游客短期凭据或会员登录会话授权）、`docs/UX.md` 0.11 的 P06、P07 会员访问与 `docs/HANDOFF.md` 0.54 的落实写法，在 `app/api/member_pay.py` 的会员路由器（前缀 `/api/member/pay`，沿用它的 `_NoStoreRoute`）上新增 `POST /api/member/pay/stripe/start` 与 `POST /api/member/pay/stripe/confirm`。设计闸门：DESIGN 1.12（提交 `acf576e`）与 HANDOFF 0.54。路由器已在 `app/main.py` 注册，未改该文件；未改 `app/api/stripe_pay.py`、`app/api/pay.py`、`app/services/`、模型、迁移、前端与设计。现有三个会员支付接口的代码未动。
- 与游客接口（SHOP-TASK-120）相同之处：请求体（只有 `order_number`，extra forbid、strict）、发起的查询参数 `lang`（`LanguageDep`，en、zh、ms，默认 en）、成功响应与结果映射、错误都相同——直接复用 `app/api/stripe_pay.py` 的 `OrderDep`（请求体读取与 422）、`StartOut`、`ConfirmOut`，以及 `app/api/pay.py` 的 `_conflict`、`_stripe_unavailable`、`GatewayDep`、`LanguageDep`。
  - 发起：`redirect` → 200 `{"result":"redirect","checkout_url":付款页地址}`；`complete` → 200 `{"result":"complete","checkout_url":null}`；`not_payable` → 409 `order_not_payable`（带订单当前 `status`）；`method_changed` → 409 `method_changed`；`under_review` → 409 `stripe_under_review`；`unavailable` → 503 `stripe_unavailable`。
  - 确认：200 `{"result":值}`，值为 `paid`、`confirming`、`not_paid`、`refunded` 之一；Stripe 不可用由 `confirm_order_payment` 归为 `confirming`，不回 503。
- 与游客接口不同之处：只凭会员会话（`require_member`，401 `member_session_required`），不读订单访问 cookie；CSRF 用 `require_member_csrf`（403 `csrf_failed`）；本人订单经现有 `_member_order` 定位（不存在、订单号不合法或不属于本人一律 404 `order_not_found`）。检查顺序与 `POST /api/member/pay/cancel` 相同：413 → 415 → 422（发起另含 lang）→ 401 → 403 → 404，之后才调用 `start_checkout` 与 `confirm_order_payment`。处理函数与依赖产生的全部响应（含错误）由路由类加 no-store；路径存在而方法不匹配的 405 由框架回答，不在此列。接口不写日志（服务层按设计记的 error 日志除外）。
- 偏离与取舍，请审阅（未改设计，未发现须停下的设计问题）：
  - `app/api/stripe_pay.py` 没有独立的映射函数（映射写在处理函数里），且本任务不许改该文件；会员发起接口在 `member_pay.py` 里照它逐条写了同样的映射，未抽出共用函数。
  - 两个接口在 `_member_order` 之前先取出会员 ID：`start_checkout` 与确认前的回滚都会让会话里的会员对象过期，写法同现有支付与取消接口。
  - 确认接口照游客接口，在授权、CSRF 与查订单（只有读取）之后先结束读事务，再调用 `confirm_order_payment`；不接受 `lang` 查询参数。
- 测试：新文件 `tests/test_member_stripe_pay_api.py` 用 TestClient 与 SQLite 内存库（夹具照 `tests/test_member_pay_api.py`），会员会话经 `issue_member_session` 签发，订单、Stripe 会话记录与退款尝试在本文件里按模型写入，以 `app.state.stripe_gateway` 注入 `FakeStripeGateway`。覆盖：会员发起建会话、只返回付款页地址且 locale 随 lang；认领的游客订单可发起；已有 open 会话返回原地址；complete；模拟途径 409 `method_changed`；非待支付 409 `order_not_payable`（带 status）；转人工 409 `stripe_under_review`；Stripe 不可用 503。确认的 paid、confirming、not_paid、refunded 各一例。同一场景下会员与游客发起接口（complete、method_changed、not_payable、unavailable）及确认接口（not_paid）的状态码与响应体逐一比对相同。两个接口各验证：未登录、会话不合法或已撤销 401；只带游客订单访问 cookie 401；会员会话加游客订单访问 cookie 访问该游客订单 404；缺、错、重复或拿游客令牌的 CSRF 403；他人订单、游客订单、不存在与不合法订单号 404；CSRF 先于查订单；未知字段 422 不回显（有无会话都是 422）；413 先于一切；415 先于会话；发起另验证非法 lang 422。所有响应（含错误）都断言带 no-store，另有一条逐一走到 200、401、403、404、409、413、415、422、503 的 no-store 测试，以及接口层不写日志的测试。每条测试的文档字符串写明它守住的设计、UX 或 HANDOFF 原句；只出自验收标准的注明「验收：」。
