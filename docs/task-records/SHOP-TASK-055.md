- 请求与错误处理（`api/adminOrders.ts`）：
  - `parseOrderId`：路径里的 ID 只接受不带符号与前导零、不超过 `MAX_ORDER_ID`（2147483647，与 `app/api/admin_orders.py` 相同）的十进制正整数；不合格时 `readAdminOrder` 归为 `missing`、`advanceAdminOrder` 归为 `failed`，都不发请求。
  - `readAdminOrder`：`GET /api/admin/orders/{内部 ID}?lang=<界面语言>`，同源 cookie、`cache: "no-store"`、带中止用的 signal。只取 SHOP-TASK-037 记录段列出的字段（`id`、`order_number`、`status`、`created_at`、`paid_at`、`lines` 每行六个字段、五个金额、`recipient` 六个字段或 null、`events` 每条三个字段、`refunds_pending`、`fully_refunded`、`csrf_token`），多出的字段不带进结果；时间字段沿用 `readRow` 对 `created_at` 的写法（字符串且 `Date.parse` 能解析），`actor_type` 只接受 guest、member、admin、system，金额与计数须为非负整数、件数为正整数，任一项不合格算失败。归为 `ok`、`none`（401）、`missing`（404）、`failed`（其他）与 `network`。
  - `advanceAdminOrder`：`POST /api/admin/orders/{内部 ID}/status`，JSON 请求体只有 `status`（`demo_packed` 或 `demo_shipped`），请求头 `X-CSRF-Token`（沿用 `api/pay.ts` 的 `CSRF_HEADER`）为详情返回的令牌，同源 cookie、`cache: "no-store"`。归为 `done`（200）、`conflict`（409 且错误码为 `order_not_advanceable` 或 `fulfilment_frozen`）、`csrf`（403）、`none`（401）、`failed`（其他，含别的 409）与 `network`。
  - 打开详情：effect 经 `startDeferred` 推迟到下一轮事件循环再调用 `openDetail`，清理时取消尚未执行的调用并中止请求，所以开发模式下 StrictMode 的「执行—清理—再执行」只发一次 GET；effect 只依赖内部 ID（与路由的 `replace`），界面语言取自打开时，之后切换语言不重新读取，商品名称等接口文字保持打开时的语言，界面文字随语言切换。200 显示详情；401 用路由的 `replace` 进入 `/admin/login`；404 与不合法 ID 在详情位置只显示 `common.error_retry` 与 `common.back`（桌面左侧列表照常显示，返回只在手机显示）；网络中断 `common.network_check`，其他失败 `common.error_retry`。读取中详情区标 `aria-busy`。
  - 离开页面或换到另一张订单时（`App.tsx` 以实际路径为 key，换订单即重新挂载），读取与推进后的重新读取都以同一 signal 中止，`settleDetail` 在 signal 已中止时不显示也不跳转；推进的 POST 本身不中止（与后台框架的退出相同），其结果同样不再更新页面。
  - 订单号、收货资料与 CSRF 令牌只在 React 状态与请求里：网址只有内部 ID 与 `lang`，令牌只在请求头，不写 localStorage、sessionStorage、cookie、历史记录或控制台。
- 推进与冻结：`admin.mark_packed` 只在 `demo_paid`、`admin.mark_shipped` 只在 `demo_packed` 时可点，其余状态禁用；`fully_refunded` 为真时两者都禁用并显示 `admin.frozen`（`role="status"`）；`admin.ship_hint` 始终显示（◆ 图形以 `aria-hidden` 标出）；可点的按钮为主按钮，禁用的为次要按钮（照视觉稿）；请求进行中两个按钮都禁用。200 后重新取详情；409（两种错误码）与 403 重新取详情并显示 `common.error_retry`；401 用 `replace` 进入 `/admin/login`；网络中断显示 `common.network_check`、其他失败显示 `common.error_retry`，这两种不重新读取、保留当前详情，按钮按原状态仍可点（再点即重发同一请求，已是目标状态时服务端回答 200）。提示为 `AdminAlert`，在按钮之后。
