- 请求与重试规则：
  - 计价：用购物车各行 SKU 与件数调用 `POST /api/checkout/quote?lang=<当前语言>`（不带 cookie）；选定国家（马来西亚另须选定州属）后加 `country_code`（与 `state_code`）。购物车、语言、国家或州属变了就重新计价，新请求发出时中止上一个，只采用最后一次请求的结果；新结果返回前继续显示上一次的结果并标 `aria-busy`，此时不能下单。计价失败在摘要处显示 `common.error_retry`。

  - 回答：201 或 200 时清空本浏览器购物车（`clearCart`），以站内导航进入 `/pay`（不带订单号或查询参数）；网络中断（fetch 抛错）时显示 `common.network_check`，每 5 秒（`RECHECK_DELAY_MS`，与 P06 相同）以同一幂等键、同一请求体重试，直到得到回答（重放由服务端按原订单回答 200，不会重复下单），离开页面即停止；409 `order_not_placeable` 时重新计价并显示 `cart.item_changed`；403 `sms_verification_required` 时页面把开关当作已开启、回第 1 步立即按开启状态重新判定（马新号码显示 `common.service_unavailable`，其他号码无错误，再继续即为 `checkout.guest_other_country`）；422 且出错类型含 `phone_invalid` 时回第 1 步，号码字段标为错误并显示 `checkout.phone_invalid`；409 `idempotency_conflict` 时丢掉原来的键（下一次提交生成新键）并显示 `common.error_retry`；503 显示 `common.service_unavailable`；其他（含别的 403、409、422 与 5xx）显示 `common.error_retry`。任何回答都不清空已填内容。
  - 电话与收货资料只在 React 状态里，不写 localStorage、sessionStorage、cookie 或历史记录，不进任何路径或查询参数；页面写入浏览器存储的只有下单成功后清空购物车。刷新后需重填。
