- 请求与重试规则：
  - 读取订单：P10 打开与切换语言时调用 `GET /api/orders/lookup?lang=<当前语言>`，打开时取 `orders[0]`，之后都按已显示的订单号取该单（与 P09 相同）。每次读取后已选件数保留，但不超过各行新的可退件数。
  - 预计金额：`refundEstimate` 对件数大于 0 的行取 `refund_estimates_sen[件数 − 1]` 再相加，只做整数仙加法；件数超出列表时（页面不会出现）返回 null，不显示合计、不能提交。全部为 0 件或有操作进行中时两个提交按钮都禁用。
  - 提交：`POST /api/orders/refunds`，请求体只有 `order_number` 与 `lines`（件数大于 0 的行，`line_index` 取订单行的行序），请求头 `Idempotency-Key`（每次提交 `crypto.randomUUID()` 新生成）与 `X-CSRF-Token`（最近一次读取时接口给的令牌）；提交期间按钮与加减控件禁用。201 或 200：把订单号交给 P09（模块变量），站内导航到 `/track/order`，P09 打开时取该单、显示 `refund.submitted` 并清除交接。409 `refund_duplicate`、`refund_nothing_left`、`refund_window_closed`：重新读取该单，分别显示 `refund.duplicate`、`refund.nothing_left`、`refund.window_closed`（危险提示条）。409 `order_not_refundable`：导航到 `/track/order`。409 `idempotency_conflict`：重新读取该单，显示 `common.error_retry`，清除待重试的申请，下次提交另生成键。403：重新读取该单取得新令牌，显示 `common.error_retry`。401（含重新读取得到 401）：整页 `order.session_expired`。其他回答（含其余 2xx、未知的 409、422、5xx）：显示 `common.error_retry`。
  - 网络中断：显示 `common.network_check`，按钮保持禁用，重新读取该单（读取也中断或失败时每 5 秒再读）；申请记录比提交时多了一笔即视为已提交（同 201）；401 整页过期；否则显示 `common.error_retry` 并记下这次的幂等键与请求行，下一次提交的请求行相同时沿用该键（同一请求内容），件数改了就另生成。离开页面时中止进行中的读取与确认。
  - 订单号与 CSRF 令牌只在 React 状态与模块变量里，不写 localStorage、sessionStorage、cookie 或历史记录，不进任何路径或查询参数；P09 链到 P10 与 P10 回到 P09 都不带订单号。
