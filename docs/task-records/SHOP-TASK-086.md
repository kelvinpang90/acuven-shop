# SHOP-TASK-086 积分的获得、预占、释放、到期与作废规则

- 到期时刻（`lot_expires_at(acquired_at)`）：取得时间（不带时区的 UTC）先截到整秒，加固定的 `MALAYSIA_UTC_OFFSET`（UTC+8，写法同 `app/services/sms_budget.py`）得马来西亚日期，加 12 个自然月（没有那一天取该月最后一天，即闰年 2 月 29 日取得的批次次年 2 月 28 日到期），取那天 23:59:59 马来西亚时间再减 8 小时换回 UTC。`is_lot_expired(expires_at, now)`：当前时间截到整秒后晚于到期时刻才算过期，到期时刻本身仍有效。获得时写入的取得时间与流水时间都是截到整秒的当前时间：MySQL 的 DATETIME 会把小数秒四舍五入（马来西亚 23:59:59.7 会进到次日），先截掉使写入的值与据以计算到期时刻的值相同。
- 余额口径：批次剩余为该批次全部流水之和；待抵扣（`debt_points`）为该会员批次为空的流水之和；可用余额（`available_points(db, member_id, now)`）为该会员未过期批次剩余之和。两个读取函数只读、不加锁，MySQL 的 SUM 返回 DECIMAL，转回 int。
- 会员行锁：每个写函数先以 SELECT … FOR UPDATE 锁住该会员的行（`populate_existing` 重新载入），锁后用于判断的订单、批次与流水一律加锁读（订单与批次另以 `populate_existing` 重新载入），读到最新已提交的状态，不沿用 MySQL 可重复读的事务快照或 ORM 缓存；批次剩余与待抵扣在 Python 里由加锁读出的流水行求和，不对聚合加锁。锁的顺序为会员 → 订单（与 `reserve_coupon` 一致）。同一会员的写因此在会员行锁上排队，批次剩余与待抵扣都不小于零——行锁只在 MySQL 上成立；SQLite 不支持行锁、SQLAlchemy 在 SQLite 上不生成 FOR UPDATE，SQLite 测试只验证锁下的判定与写入。写函数只 flush、不提交，不写日志；积分一律 int。积分不是 int（含 bool、小数、字符串、空）抛 `TypeError`、负数抛 `ValueError`，ID 不是正整数抛 `ValueError`，当前时间不是 datetime 抛 `TypeError`、带时区抛 `ValueError`，消息不含会员资料。
- 获得（`earn_points(db, member_id, order_id, points, now)`，支付成功时调用）：锁会员行与订单行后核对会员为 active 且订单的 `member_id` 等于该会员，否则抛 `ValueError`；同一订单已有批次时返回已有批次、不再写（重复调用不重复发放）；获得积分为 0 时不写任何记录、返回 `None`；大于 0 时写一个批次（取得时间为当前时间，到期时刻按上条）与一条 `earn`，随后若有待抵扣，以 min(待抵扣, 获得积分) 成对写两条 `debt_repay`（一条从新批次扣出、一条批次为空减少待抵扣，订单都记该订单），返回新批次。
- 预占（`reserve_points(db, member_id, order_id, points, now)`，下单时调用）：同样核对会员与订单，同一订单已有 `redeem` 流水时抛 `ValueError`；抵扣积分为 0 时不写记录；可用余额不足时抛 `InsufficientPoints`（消息只有 `insufficient points`）且不写记录；否则按到期时刻升序、同时刻按批次 ID 升序逐批写 `redeem` 直到凑足（先到期先使用）。支付成功时不另写流水：预占即抵扣，之后批次到期也照常有效（Kelvin 决定 4）。返回 `None`。
- 释放（`release_points(db, order_id, now)`，取消或支付超时时调用）：先以普通读从该订单的 `redeem` 流水取会员 ID（注销后订单的 `member_id` 已清空），锁会员行后加锁读该订单在各批次的 `redeem`、`release` 与 `refund_return`，每个批次的净抵扣（求和取负）大于 0 时写一条等量的 `release`；该批次此时已过期则紧接着写等量的 `expire`（Kelvin 决定 4），未过期而会员不是 active 则紧接着写等量的 `forfeit`（已过期优先记为到期，与作废一致）。`expire` 与 `forfeit` 的订单记批次的来源订单。按到期时刻与批次 ID 升序写。没有可释放的净抵扣时不写记录、返回 0（重复调用不出错）；返回释放的积分数。不要求会员仍为 active。
- 到期（`expire_points(db, now, batch_size)`，供之后的定时任务调用）：`batch_size` 须为正整数（0、负数、bool 与非 int 都抛 `ValueError`）。先以普通读按会员 ID 升序、同一会员内按到期时刻与批次 ID 升序选出至多 `batch_size` 个已过期且剩余大于 0 的批次，再按会员 ID 升序逐个锁会员行（多个会员的锁总按同一顺序取得），加锁读重新核对这些批次已过期且剩余大于 0 后各写一条等于剩余的 `expire`（已预占的部分已从剩余里扣掉，自然被跳过）。返回写了 `expire` 的批次数，可重复运行。
- 作废（`forfeit_points(db, member_id, now)`，注销时调用）：锁会员行（不要求 active），对该会员剩余大于 0 的批次各写一条等于剩余的 `forfeit`，已过期的写 `expire`；待抵扣不作废。返回作废（`forfeit`）的积分数，即作废前的可用余额。
- 偏离：未改设计，未发现须停下的设计问题。说明几处取舍，请审阅：
  - 获得与预占先核对会员与订单，再看同一订单是否已有批次或 `redeem`：会员注销后再次调用获得会抛 `ValueError` 而不是返回已有批次；获得积分为 0 或抵扣积分为 0 时同样先核对。
  - 同一订单已有批次时返回已有批次，不比较这次给的获得积分与已有批次是否相同（获得积分来自订单快照，由 SHOP-TASK-090 保证）。
  - 预占与获得都不核对订单状态与订单上的 `points_redeemed`、`points_earned` 快照，照用调用方给的积分数；由 SHOP-TASK-088、090 保证。
  - 释放时该订单的 `redeem` 流水属于多个会员（正常不会出现）抛 `ValueError`；会员行不存在抛 `ValueError`。释放不锁订单行，避免与调用方先锁订单的取消流程形成相反的加锁顺序。
  - 到期函数选候选批次用普通读（MySQL 可重复读下可能是事务快照），锁后以加锁读重新核对才写，快照里已被处理的批次只会被跳过；返回值是实际写了 `expire` 的批次数，可能少于候选数。
  - 作废函数返回只计 `forfeit`，不计同时为已过期批次写的 `expire`。
- 留给之后的任务：退款的返还与追回（不足记待抵扣）留给 SHOP-TASK-087；接线留给之后的任务——会员下单时预占（SHOP-TASK-088、089）、模拟支付成功时获得与取消及超时时释放（SHOP-TASK-090）、注销时作废（SHOP-TASK-094）、会员中心的积分查询（SHOP-TASK-095）、积分到期的定时任务（SHOP-TASK-096，调用 `expire_points` 并逐批提交）。
