# SHOP-TASK-178 每行 1000 件、整单 2,000 件与整单金额上限（计价与下单）

- [x] 依据：`docs/DESIGN.md` 1.18（提交 `5ba9796`）「计价、优惠、积分与库存」第 8 条（每行件数 1–1000、整单件数合计不超过 2,000、整单金额上限 99,999,999 仙、退款申请每行上限随之改为 1000）；`docs/HANDOFF.md` 0.74 记录的落实写法。设计闸门：DESIGN 1.18（提交 `5ba9796`）第 8 条与 HANDOFF 0.74，计价与下单的件数和金额上限。不改模型与迁移、`app/services/pricing.py`、`app/services/ordering.py`、前端与设计，不装依赖。
- [x] 常量（`app/services/checkout.py`）：`MAX_LINE_QUANTITY` 由 99 改为 1000，新增 `MAX_ORDER_UNITS = 2000` 与 `MAX_ORDER_AMOUNT_SEN = 99_999_999`，注释与模块说明引用 DESIGN 1.18 第 8 条。计价、游客下单、会员下单（都用 `app/api/checkout.py` 的 `QuoteLineIn`）与退款申请（`app/api/refunds.py` 的 `RefundLineIn`，积分预估同一模型）的请求体本来就经 `MAX_LINE_QUANTITY` 校验，常量一处改动即全部生效：1000 件照常，1001 件 422。退款仍不得超过该行的购买件数，服务层判定不变。
- [x] 件数上限：`CheckoutQuote` 在 `can_place_order` 之后依次加 `unit_limit`（恒为 2000）、`units_over_limit`、`amount_limit_sen`（恒为 99999999）、`amount_over_limit`。`units_over_limit` 按请求里所有行的件数合计（含不可购买的行）是否大于 2000；超出时 `can_place_order` 为假，各行的状态与标注照现有规则不变。
- [x] 金额上限：给了收货国家时按 `subtotal_sen` 加运费、没给时按 `subtotal_sen`，大于 99,999,999 时 `amount_over_limit` 为真，`can_place_order` 为假，不调用 `reference_amount`（`fx_reference` 为 null）；`total_sen` 照给。`subtotal_sen` 改为各计价行（正常、超出限购与库存不足）`line_subtotal_sen` 之和，不再调用 `price_order`（与原来的值相同，件数超出时也不逐件展开），`checkout.py` 随之不再 import `pricing`。
- [x] 会员计价（`app/services/member_ordering.py`）：`MemberCheckoutQuote` 在 `can_place_order` 之后带上这四个字段（取自 `quote_cart`）；`units_over_limit` 或 `amount_over_limit` 为真时与有不正常行走同一分支返回——`coupon_applicable` 为空，`coupon_discount_sen`、`points_cap`、`points_redeemed`、`points_earned` 为 0，`points_accepted` 为假，`available_points` 照常为可用余额。`app/api/member_orders.py` 的 `MemberQuoteOut` 在 `can_place_order` 之后加同样四个字段并照传。
- [x] 下单：游客下单（`app/services/ordering.py`）与会员下单（`place_member_order`）不改代码，二者本来就按 `quote_cart` 的 `can_place_order` 判定，超出任一整单上限时抛 `OrderNotPlaceable`、接口回 409 `order_not_placeable`，不写订单、不动库存，不新增错误码。`app/api/checkout.py`、`app/api/orders.py`、`app/api/refunds.py` 与 `app/api/member_orders.py` 说明里的「1–99」「1 到 99 件」改为 1–1000（前三个文件除说明外未改）。
- [x] 测试：
  - 新增 `tests/test_order_caps.py`（SQLite 内存库，打开外键检查；时间固定传入 `NOW`），每条写明守住的第 8 条原句：两个常量；2000 件不超出且可下单，2001 件（全是正常行）超出、各行仍为 ok、不可下单；含不可购买的行一起计数（1999 + 1 不超、1999 + 2 超）；小计加运费恰为 99999999 不超出且有参考外币，多 1 仙即超出、`fx_reference` 为 null、不可下单；没给收货国家时只按小计判断（恰为上限不超、多 1 仙超），同一小计给了国家加上运费即超出；计价接口超出时 200 并带标记与上限；游客下单经接口在件数与金额超出时都回 409 `order_not_placeable`、没有订单与逐件行、库存不变，另有小计加运费恰为上限时 201 的对照；会员下单在服务层调用 `place_member_order`，两种超出都抛 `OrderNotPlaceable`、没有订单、库存不变；会员计价两种超出时照上一条返回，另有恰好 2000 件时照常判定券与积分的对照。
  - 现有测试只把「100 件被拒」改为「1001 件被拒」：`tests/test_purchase_limit.py` 的 `test_line_quantity_99_is_accepted_and_100_is_rejected` 改名为 `test_line_quantity_1000_is_accepted_and_1001_is_rejected`（99 件被接受的对照改为 1000 件）；`tests/test_checkout_quote.py` 的 `quantity-100` 改为 `quantity-1001`，`test_limits_are_inclusive` 的件数 99 改为 1000；`tests/test_guest_order.py` 的 `quantity-100` 改为 `quantity-1001`；`tests/test_refunds.py` 与 `tests/test_refund_points_estimate_api.py` 的 `quantity-over-99` 改为 1001 件、id 改为 `quantity-over-1000`（退款两处不加 1000 件的对照，服务层另按购买件数拒绝）。这几处文档字符串里的「1 到 99」改为 1–1000，改动的用例写明引用 DESIGN 1.18 第 8 条的哪一句。原因：每行上限由 99 改为 1000，100 件不再被拒。
  - 列出计价响应完整字段的两处加上四个新字段：`tests/test_checkout_quote.py` 的 `test_ok_line_has_exactly_the_public_fields` 期望字典（`unit_limit` 2000、`units_over_limit` 假、`amount_limit_sen` 99999999、`amount_over_limit` 假）与 `tests/test_member_orders_api.py` 的 `GUEST_QUOTE_FIELDS`。其余断言不变。
- 偏离与说明：
  - 新测试比验收标准多了三条对照：游客下单在小计加运费恰为上限时 201、会员计价恰好 2000 件时照常判定券与积分、同一小计给不给国家结果不同；用来说明拒绝来自上限而不是别的校验。
