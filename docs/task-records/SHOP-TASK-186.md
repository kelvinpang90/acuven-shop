# SHOP-TASK-186 后台商品的列表、读取、新建与保存接口

- [x] 依据：`docs/DESIGN.md` 1.18（提交 `5ba9796`）「计价、优惠、积分与库存」第 11 条；`docs/UX.md` 0.17 的 A04（列表、单件编辑、新建、保存后的取值不合格与商品已被改动）；`docs/HANDOFF.md` 0.77 的落实写法（取值不合格回 422 `product_invalid`，商品已被改动回 409 `product_changed`，读取不存在的商品回 404 `product_not_found`；请求体上限 256 KB、逐块读取；JSON 字段名与 SHOP-TASK-183 的请求结构同名；金额以整数仙收发）。设计闸门：DESIGN 1.18（提交 `5ba9796`）第 11 条与 HANDOFF 0.77。本任务只把 SHOP-TASK-183 至 185 的服务层接成接口，不改服务层、模型与迁移、现有测试、前端与设计；页面 A04 另行登记。
- [x] 接口（新增 `app/api/admin_products.py`，路由类为 SHOP-TASK-027 的 `_NoStoreRoute`，`app/main.py` 注册）：
  - `GET /api/admin/products`：`require_admin`（401 `admin_session_required`）→ `products`（`load_admin_products` 的全部项，字段依次为 `id`、`slug`、`name_en`、`name_zh`、`name_ms`、`is_active`、`category_id`、`category_name_en`、`category_name_zh`、`category_name_ms`）与由 cookie 算出的 `csrf_token`。不写审计。
  - `GET /api/admin/products/{product_id}`：`require_admin`（401）→ 路径 ID（`_product_id`，照 `admin_orders.py` 的 `_order_id`：不带符号与前导零、至多 10 位、不超过 2³¹−1，不合法 422 `product_id_invalid`，固定消息）→ `load_admin_product`，不存在 404 `{"detail": "product_not_found"}`。字段同服务层的 `AdminProduct`（含 `options[].values[]`、`variants[]` 的 `option_value_ids` 与 `images[]`），空文案为 null。不写审计。
  - `POST /api/admin/products`：请求体逐块读取超过 256 KB 即 413 → 不是 JSON 415（`_write_body`，照 `admin_shipping_rates.py` 的 `_save_body`，只有上限不同）→ `require_admin`（401）→ X-CSRF-Token（403 `csrf_failed`）→ 请求体模型 `ProductIn`（`extra="forbid"`、`strict=True`，错误经 `_body_errors` 不回显）→ `create_product`。成功 201 与新商品（同单件读取）。
  - `PUT /api/admin/products/{product_id}`：413 → 415 → 401 → 403（先声明 `CsrfDep`，照 `admin_coupons.py`）→ 路径 ID 422 → 请求体模型 `ProductSaveIn`（同新建，另有必填的严格整数 `version`）→ `save_product`。成功或未变都 200 与保存后的商品。
  - `ProductInvalid` 回 422 `{"detail": "product_invalid"}`，`ProductChanged`（含保存时商品不存在）回 409 `{"detail": "product_changed"}`；异常里的英文说明不回给调用方。管理员 ID 在调用服务层之前取出。不写日志。
- [x] 请求体模型：`ProductIn`、`OptionIn`、`ValueIn`、`VariantIn`、`ValueRefIn` 与 `ProductInput`、`OptionInput`、`ValueInput`、`VariantInput`、`ValueRef` 同名一一对应；`options`、`values`、`variants`、`option_values` 为数组；三语名称与描述为字符串（可为空串）；整数字段不收布尔值、字符串与浮点数。可省略的 `id`、`temp_id`、`option_values` 照 `admin_site_settings.py` 的写法：类型不允许 None（显式 null 即 422），默认值只为省略时占位，是否提交看 `model_fields_set`，省略的转成服务层的 None。`id` 与 `temp_id` 的搭配（两者都有或都没有、新建带行 ID、已有 SKU 带 `option_values`、新增 SKU 缺 `option_values` 等）不在模型里判断，交给服务层回 `product_invalid`。
- [x] 测试：新增 `tests/test_admin_products_api.py`（写法照 `tests/test_admin_shipping_rates_api.py`；种子商品经 `create_product` 造；每条测试的文档字符串写明它守住的第 11 条、A04、HANDOFF 0.77 或本任务验收的约定）。覆盖四个接口没有会话 401（路径 ID 不合法也先 401）；新建与保存 CSRF 缺少、为空、不一致 403，且先于请求体与路径 ID 的 422；超过 256 KB 413 先于 415、登录与路径检查；不是 JSON 415；恰好 256 KB 照常处理；多出字段（含 slug、代码、SKU 与 `available_stock`）、缺字段、null（含可省略的 `id`、`temp_id`、`option_values`）、布尔值当整数、浮点数价格、字符串整数、数字名称、对象当数组、新建带 `version`、缺或类型不对的 `version` 都 422 且不回显；路径 ID 为 0、负数、非数字、小数、前导零、`+1`、超出 INT 上限与超长 422，且先于请求体；列表的字段、顺序（从新到旧、含未上架）与 `csrf_token`；单件的字段、顺序、代码、规格值 ID 与图片，没有规格名的商品；GET 不存在 404；新建 201、返回的代码（slug、沿用全站的规格名与规格值代码、SKU、同名时 slug 加 `-2`、没有规格名时 `-std`）与审计；ValueRef 同时带或都不带 `id` 与 `temp_id`、新建带行 ID、取值超范围、四个规格名、重名、上架条件、分类停用或不存在都 422 `product_invalid`；保存成功 200、版本加一、逐项审计；未变 200 不写审计；保存时新增规格值与 SKU（以 `id` 与 `temp_id` 混合引用）；已有 SKU 带 `option_values`、已有行另带 `temp_id`、新增规格名、新增与已有组合相同 422；版本号不符、漏列行、未知行 ID、别的商品的 SKU、PUT 不存在的商品与读取后被另一处改过都 409；取值不合格与版本过期同在时先 422；所有响应带 no-store、应用不记日志；该路径下只有这四个路由。
- 偏离与取舍：
  - `product_invalid` 与 `product_changed` 回答前都先 `session.rollback()`：服务层第一步不通过时还没有回滚（`create_product` 与 `save_product` 的检查在 try 之外），回滚一次无副作用。
  - 规格名的 `id` 在模型里可省略：新建时不带、保存时带；保存时省略即「新增规格名」，由服务层回 `product_invalid`。
  - 服务层未捕获的数据库错误不另转成 503（同 `admin_categories.py`，验收未列出）。
