- 接口 `POST /api/orders/refunds`（不读会员会话；订单号只在请求体里）：请求头 `Idempotency-Key`（规则同 SHOP-TASK-020）与 `X-CSRF-Token`；请求体只有 `order_number`（1 到 16 个字符的字符串）与 `lines`（1 到 20 项，每项 `{"line_index": 订单行序（order_items.line_index，≥ 0 的整数）, "quantity": 1 到 99 的整数}`，行序不重复），多出字段 422。处理顺序（每一步不通过即停止）：逐块读请求体，超过 8 KB 即 413（先于一切校验）→ 不是 `application/json` 即 415 → 幂等键与请求体一并校验 422 → 按订单号查订单 ID，以当前 cookie 与 `lookup` 范围调用 `check_order_access`（订单号不存在、授权过期、不属于该会话或范围不符一律同一个 401 `access_expired`；`guest_checkout` 授权不能用）→ `check_csrf_token`（403 `csrf_failed`）→ 才查幂等键与订单：
  - 幂等：指纹是 `{"lines": [{"line_index": 行序, "quantity": 件数}, …（按行序）], "order_id": 订单 ID}` 的 JSON（键排序、无空白）的 SHA-256 `hexdigest`；先按幂等键查申请，指纹相同（常量时间比较）200 与原申请，不同 409 `idempotency_conflict`，都不再写入。
  - 之后依次：订单未支付（待支付或已取消）409 `order_not_refundable`；当前时间晚于退款截止时间 409 `refund_window_closed`（`refund.window_closed`）；行序不属于该订单 422；该单已没有任何可退件 409 `refund_nothing_left`（`refund.nothing_left`）；任一行件数超过该行可退件数 409 `refund_duplicate`（`refund.duplicate`），整笔不受理、不部分受理。已发货、已完成的订单照常可申请。
  - 通过时在同一事务里写申请（`requested`、申请方 `guest`、审核时间为空）、各申请行与逐件记录（占用标记 1），201。新写与重放的响应体都是 `{"status": …, "amount_sen": …, "lines": [{"line_index": …, "quantity": …}]}`（各行按行序）。
  - 并发：写入撞上唯一约束（同一幂等键，或同一件已被另一笔有效申请占用）时回滚，再按幂等键重新查询：同键同指纹返回原结果、同键不同指纹 409 `idempotency_conflict`，否则按重新读取的可退件 409 `refund_nothing_left` 或 `refund_duplicate`。
  - 所有响应（含错误）带 `Cache-Control: no-store`（沿用 `app/api/order_lookup.py` 的路由类 `_NoStoreRoute`）；422 每条错误只有 `type`、`loc`、`msg`（沿用 `app/api/pay.py` 的 `_body_errors`），不回显请求内容；不写日志。
