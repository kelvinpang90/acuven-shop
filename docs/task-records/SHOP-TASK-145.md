# SHOP-TASK-145 短信验证组件 V1 的注册登录与重设密码用途

设计闸门：DESIGN 1.12（提交 acf576e）「权限与资料保护」第 1、3 条与「失败、并发与重试」与 HANDOFF 0.58。内容与文案依据 docs/UX.md 0.12 的 V1、docs/UX-COPY.md 0.13；样式依据视觉稿 V1-start、V1-code-wrong、V1-errors、V1-register-unavailable、V1-no-change 与 V1-verified。

- [x] 新组件 `frontend/src/components/SmsVerify.tsx`（结构照 `AdminStoreDesignPage.tsx`：导出把请求结果变成状态改动的纯函数 `sendStep`、`verifyStep` 与输入、挑战、进行中的纯函数，接收 AbortSignal 与回调的异步函数 `sendCode`、`submitCode`、`mountChallenge`，只依赖 props 的 `SmsVerifyView`，以及默认导出的 `SmsVerify`）。
  - props：`purpose`（`register`、`login` 或 `reset_password`）、`smsEnabled`（短信验证开关）、`siteKey`（人机挑战公开 key，可为 null）、`onVerified`（验证通过的回调）、`guestTo`（auth.continue_guest 的站内前台去向，类型为 `RoutePath`；只有 register 与 login 必填，reset_password 的类型里没有这一项），以及可选的 `challenge`（挑战加载器，默认 Turnstile，测试与之后的页面可注入）。
  - 用途：register 与 login 以同名 purpose 调 `sendSmsCode` 与 `smsLogin`，回调收到 `{ kind: "member", created }`；reset_password 以同名 purpose 调 `sendSmsCode` 与 `verifyPasswordReset`，回调收到 `{ kind: "registered", csrfToken }` 或 `{ kind: "not_registered" }`。请求都经 SHOP-TASK-144 的 `frontend/src/api/memberAuth.ts`，未改 `frontend/src/api/`。验证码以最近一次 sent 时的号码（输入原文与地区）提交。
  - 组件不跳转、不写浏览器存储；手机号、验证码与令牌只在组件状态与请求体里。卸载时中止进行中的发送与验证，之后的结果不再更新、回调不再调用。传给事件属性的处理函数都不返回 Promise（以 `void` 丢弃异步函数的结果）。
- [x] 状态与提示：
  - 号码：国家码下拉只有 +60（MY，默认）与 +65（SG），以 auth.phone 的标签作读屏名称（与结账第 1 步同一写法）；其下 auth.sms_scope；register 与 login 另有 auth.claim_notice。phone_invalid（发送或验证）在号码下显示 checkout.phone_invalid。
  - 发送：完成挑战前、发送或验证进行中按钮禁用（进行中标 aria-busy）；每次发送（无论结果）之后作废令牌并重置挑战。sent 后发送按钮换成 auth.code_sent（{phoneMasked}）、验证码输入（auth.code）、auth.verify_submit 与 auth.resend_code（重发同样要先完成挑战）。重发成功时清空已填的验证码。
  - {phoneMasked}：输入以 + 开头时为 + 与其后的全部数字，否则为国家码加输入里的数字（去掉开头的一个 0），再照 `app/api/member_auth.py` 的 `mask_phone` 保留前 3 个与最后 4 个字符、中间换成星号（不足 8 个字符整串换成星号）。只用于显示。
  - 发送结果：captcha_failed → auth.challenge_failed；rate_limited → common.rate_limited；not_whitelisted → register/login 为 auth.not_supported_country 与 auth.continue_guest，reset_password 为 auth.sms_not_sent_no_change；undeliverable 与 suspended → register/login 为 auth.sms_failed 与 auth.continue_guest，reset_password 为 auth.sms_not_sent_no_change；disabled → 整个组件换成 auth.sms_paused（register/login 另有 auth.continue_guest）；network → common.network_check；failed → common.error_retry。失败后号码输入仍在，可改号或重试。
  - 验证结果：wrong → 验证码下 auth.code_wrong（不出现 auth.continue_guest）；unavailable → common.service_unavailable，留在验证码输入，可再提交或重发；disabled → 同开关关闭；phone_invalid → checkout.phone_invalid；network、failed 同上。通过时先调用回调，再进入已验证状态：只留 auth.code_sent 一行（遮掩后的号码只在这里出现），号码、挑战、验证码输入与全部按钮收起，结果文字由嵌入的页面显示。
  - 整体替换：开关关闭（或流程中 disabled）为 auth.sms_paused，register/login 另有 auth.continue_guest；开关开启而公开 key 为 null 时 register/login 为 auth.sms_failed 与 auth.continue_guest，reset_password 为 auth.sms_not_sent_no_change。替换时不显示号码、auth.sms_scope、auth.claim_notice、挑战与按钮。auth.continue_guest 为指向 `guestTo` 的站内链接（`Link`）。
- [x] 人机挑战的接法：新文件 `frontend/src/components/turnstile.ts`。`ChallengeLoader` 只有一个 `render(container, siteKey, language, { onToken, onLost })`，返回带 `reset` 与 `remove` 的挑战；默认实现 `TURNSTILE` 在第一次渲染时插入官方脚本（常量 `TURNSTILE_SCRIPT_URL`，`render=explicit`；加载失败时移除脚本元素，下次重新加载），以 `turnstile.render` 显式渲染，language 参数按界面语言取 en、zh-CN、ms，`expired-callback`、`error-callback` 与 `timeout-callback` 都归 `onLost`。组件经 `mountChallenge` 在挑战容器（View 里的空 div，以 callback ref 交给组件）出现时渲染、容器移除（替换、已验证）或界面语言、公开 key 变化时移除；移除之后才到的令牌、失败与渲染结果都不再处理。界面语言或公开 key 变化时先前的令牌作废（渲染时更新，同 AdminStoreDesignPage 换语言的写法）。脚本加载或渲染失败、令牌过期显示 auth.challenge_failed，取得新令牌后收起；服务端 captcha_failed 与挑战失效同时出现时只显示一次。
- [x] `frontend/src/i18n/copy.ts` 按 UX-COPY 0.13 逐字加入 auth.sms_scope、auth.challenge、auth.challenge_failed、auth.send_code、auth.resend_code、auth.code_sent、auth.code、auth.verify_submit、auth.code_wrong、auth.not_supported_country、auth.sms_failed、auth.sms_paused、auth.sms_not_sent_no_change、auth.continue_guest 与 auth.claim_notice（每种语言一行）。用到的 common.rate_limited、common.service_unavailable、common.network_check、common.error_retry、auth.phone 与 checkout.phone_invalid 字典里已有。
