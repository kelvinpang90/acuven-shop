## 身份与目标

- `project_id`：`acuven_shop`；`task_id_pattern`：`^SHOP-TASK-[0-9]{3}$`，已于 2026-09-29 确认。
- Acuven 品牌的公开网店演示站，面向有兴趣购买网店方案的潜在客户。目标是让访客亲自体验完整流程，之后自行通过 WhatsApp 联系 Acuven；不在站内收集销售线索。
- 以通用示例实物商品演示。所有商品、金额、库存、支付、运费、发货与退款均为演示，不发生真实交易或履约。页面及关键操作须持续、清楚地标注这一点。
- 预计初期每天几十名访客。首版支持英文、中文、马来文切换，默认英文；桌面与手机均可使用。

## 访客与会员流程

1. 浏览、搜索、按分类及属性筛选示例商品；选择颜色、尺寸等规格与数量，加入购物车。商品在列表与首页只显示 MYR 价格：有多于一个启用规格时一律显示最低单价加「起」，即使各规格同价。
2. 未登录访客结账先填手机号（默认区号 +60，可选其他国家码或以 `+` 开头输入）：马来西亚、新加坡号码须先通过短信验证码验证，通过后自动注册会员（已注册则直接登录），再进入下单与模拟支付；其他国家号码不发短信，以游客下单，该号码即订单的收货电话与查单凭据，另填自由文本收货人及全球收货地址。马新号码短信无法送达或短信服务停发时，可改为游客下单。演示站允许填写虚构资料（马新结账手机号除外，须能收短信），在表单附近告知不真实扣款或发货、资料仅用于演示且收货资料会长期保存；不设单独确认勾选框。游客下单后，当前浏览器在 30 分钟内凭仅限该单的短期凭据支付、重试、取消并查看结果（含收货资料）；待支付订单可由下单者在支付页取消。
3. 结账展示 MYR 商品小计、优惠券与积分抵扣、示例运费、MYR 合计；不单列税费。优惠券与积分抵扣两行只对会员显示，游客（不能用券与积分）的结账摘要不显示这两行。按国家配置示例运费，马来西亚按州属细分，未单独配置的国家使用统一“其他国家”运费。按固定演示汇率显示访客国家货币参考金额，并标明仅供参考。
4. 模拟支付仅选择支付方式并点击成功或失败，不输入银行卡资料、不接真实支付服务。失败可重试且不重复下单。
5. 管理者在后台推进模拟发货；访客以订单号及下单电话查询订单，查看完整收货资料，并在查询页确认收货，查单通过后该单在本浏览器保持 30 分钟；会员也可在“我的订单”确认收货。该查询方式不使用短信验证码；安全限制及剩余风险见设计文档。
6. 访客（查询页）或会员（“我的订单”）可在模拟支付成功后 30 天内申请整单或部分商品退款，模拟发货及确认收货后仍可申请。只选择商品和数量，由系统计算金额；示例运费不退。管理员审核批准或拒绝，绝不发生真实退款。

## 会员、优惠与积分

- 会员使用国际手机号格式注册，注册、结账验证、短信登录与忘记密码时发送真实短信验证码；初期仅向马来西亚和新加坡手机号发送，其他地区仍可游客下单。会员可用手机号加密码或手机号加短信验证码登录；结账时自动注册的账号尚未设密码，可在会员中心设置；密码至少 8 位。注销账号须以短信验证码确认。手机号归属账号直至用户主动注销，长期未登录也不自动注销；结账手机号旁告知会自动注册及保留期限，不设勾选框。
- 注册会员可在“我的订单”查看历史订单、积分及优惠券，并对自己的订单确认收货、申请退款。手机号注册后自动认领该号码最近 30 天的游客订单。
- 只有会员可使用优惠券与积分。管理员可创建、停用固定金额或百分比优惠券，并设置有效期、最低消费及使用次数上限；优惠券和积分可叠加。
- 演示积分按实际支付的商品金额每 RM1 获 1 积分，100 积分抵 RM1；取得后 12 个月到期。游客结账提示无积分并引导注册。积分规则与退款后的回收见设计文档；货币最小单位称仙（sen），不与积分混用。

## 管理后台

- 首版一个管理员账号。可维护商品、图片、分类、规格、规格库存、价格、优惠券、运费区与演示汇率；可查看订单原始收货资料、推进发货状态、审核退款；可装修店铺（见下节）。
- 每天自动将示例库存恢复到管理员设置的初始值，历史订单、退款与积分继续保留。管理员可查看库存重置结果。
- 后台与前台均支持英文、中文、马来文。后台固定使用一套中性样式，不随店铺主题变化。

## 店铺装修

让潜在客户看到同一家网店可以装修成不同风格（Kelvin 2026-09-30 决定，首版就做）。

- 管理员在后台「店铺装修」页从 10 款预设主题中选一款。所有主题共用同一套页面版式与组件，只改变配色、字体、圆角、边框粗细、主视觉图块形状与演示横幅纹样；不改变页面结构、流程、去向与文案。
- 每款主题提供若干预先校过对比度的主色，管理员只能从中选一个，不能输入任意颜色。
- 管理员可上传店铺标志图，显示在前台页头与页脚、代替文字品牌 ACUVEN SHOP；也可移除，恢复文字品牌。标志图沿用商品图片的格式、大小与存储规则。
- 首页由四个区块组成：主视觉、演示怎么玩、按分类浏览、精选商品。管理员可调整它们的顺序与显示或隐藏；区块文案仍来自三语文案表，管理员不编辑文字。
- 每款主题都有浅色与深色两套，前台按访客设备的浅色或深色设置自动切换；访客不能自行切换主题或深浅色。
- 演示横幅、各页演示提示与关键操作旁的演示提示在所有主题下都显示且清楚可读，装修不能隐藏或弱化它们；首页的演示提示放在任何可隐藏区块之外。
- 装修保存后对所有访客生效，只影响外观，不影响订单、金额、库存、积分与个人资料。修改记入后台审计记录。

## 明确不做

- 不做多商家入驻、真实收款、真实物流下单、真实退款或税费计算。
- 此前“不做跨境”已被 Kelvin 后续决定覆盖：首版须演示全球收货地址、全球示例运费与参考币种。此冲突已按较新决定解决；旧范围不得继续作为实现依据。
- 不提供真实银行卡输入；不以站内联系表单替代 WhatsApp 联系入口。
- 首版不提供后台导出，也不提供访客删除收货资料的能力。
- 店铺装修首版不做：自定义文案或图片区块、新增或复制区块、任意颜色与字体、自定义主题、访客自选主题或深浅色、装修草稿与定时发布、后台换肤。

## 上线验收标准（原 1.0 已批准；备份残留条款修订候批）

- 三种语言及桌面、手机上，访客能完成搜索筛选、规格选择、马新号码结账短信验证并自动注册或登录、白名单外号码游客下单、游客凭短期凭据支付与取消待支付订单、模拟支付失败重试与成功、订单查询、确认收货及退款申请；界面明确显示演示性质。
- 管理员能维护带图片与规格库存的商品、优惠券与全球运费规则，处理发货及部分退款；每日库存重置不改动历史订单或积分。
- 管理员能切换 10 款主题、选择主色、上传与移除标志、调整首页区块的顺序与显隐，保存后前台三种语言、桌面与手机、浅色与深色都随之改变；每款主题的正文、按钮文字与演示提示达到可读对比度（正文 4.5:1，控件边框与演示标记 3:1），演示横幅与演示提示在任何装修设置下都可见。
- 马来西亚和新加坡访客能用真实短信完成结账验证与自动注册、密码设置与重设、密码登录与短信登录、以短信验证码确认注销；白名单外或无法送达短信时明确提示并保留游客下单能力。短信服务账号开通、两国实际覆盖、费用与限流是上线依赖，不能在未验证时宣称可送达。
- 重复提交不产生重复订单、重复支付或重复退款；价格、优惠、积分、运费及库存由服务端计算，并有并发与失败重试测试。
- 收货资料在线长期保存，不删除、不匿名化（Kelvin 2026-09-29 决定，风险见设计文档）。会员注销时删除的手机号与密码哈希，仍会在共享 MySQL 的 binlog（残留期为当前 binlog 文件的轮换间隔 + 3 天）与整实例备份（实际保留 N 天）中残留，轮换间隔与 N 待运营者核实，核实前没有确定的天数上限。验收还要核实轮换间隔、N、共享备份确实到期清理，以及管理员权限、账号注销、短信限流和注销删除失败告警。
- 关键流程通过 CI 与人工浏览器验收。对外发布前填入 WhatsApp 联系方式及短信服务凭据，均通过配置提供，不写入仓库。

## 技术栈与理由

建议方案，待 Kelvin 确认：

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 前端 | TypeScript、React、Vite；三语字典与响应式页面 | `ai_billing_hub`、`rs-roof-pms` 已使用该组合，适合商品列表、购物车、会员与后台交互。Vite 产物为静态文件，可由现有反向代理服务。 |
| 后端 | Python、FastAPI、Pydantic、SQLAlchemy、Alembic | 上述 Acuven 项目已有经验；用单个后端统一处理订单事务、认证、金额、积分及个人资料，避免把规则放在浏览器。 |
| 数据库 | 共享 `infra_mysql` 中的本项目独立库，使用 InnoDB 事务；数据库账号只授权本库 | Kelvin 已决定沿用 Acuven 惯例，演示站用户少，无须单独数据库容器。订单、库存、优惠与积分依赖事务及约束；共享备份残留见下文。 |
| 定时任务 | 与 API 共用 Python 业务代码的独立后台进程 | 负责每日示例库存重置、积分到期及超时订单清理；任务可重复运行、失败向运营告警邮件报告。初期不用 Celery。 |
| 图片 | 私有持久卷存原图与处理后的展示图，由后端校验与管理 | 初期每日几十访客，先复用单机 Docker 部署，不增加对象存储账号；须纳入备份并限制格式、大小与访问。 |
| 短信 | 推荐 Twilio Verify，后端保留短信服务接口；备选 Twilio Programmable Messaging + 自建验证码，待 Kelvin 选择 | Verify 托管验证码生命周期并提供防欺诈能力，减少自行维护的认证逻辑；Messaging 对短信内容控制更细，但验证码存储、重试和防刷都由本项目负责。两者均有覆盖、地区限制和费用，不能保证全球送达。 |
| 限流与人机验证 | 共享 `infra_redis` 分配给本项目的独立库编号保存短时计数；短信发送前验证人机挑战 | 多 API 进程共用计数。Redis 数据丢失时短时计数清零可接受；短信每日总量和费用预算另由本项目 MySQL 按日记录兜底，Redis 或 MySQL 不可用时停发短信。短信目的地白名单初期为马来西亚和新加坡，实际送达仍需运营验证。 |
| 备份 | 共享实例每天以 `mysqldump --all-databases` 备份全库；备份实际保留 N 天待运营者核实；binlog 残留期为当前文件轮换间隔 + 3 天，轮换间隔待核实 | 无法排除本项目的表；收货资料本就长期保存，备份残留对它无额外影响；会员注销删除的手机号与密码哈希仍会在这些副本中留至注销后 max(binlog 残留期, N) 天。上线前必须核实轮换间隔、N 与共享备份会按期清理。运营者可选择在 `vps_infra` 每天定时执行 `FLUSH BINARY LOGS`，使 binlog 残留期约为 3 天；本项目只记录此依赖。 |
| 告警 | 运营告警邮件 | 注销删除、备份边界、短信费用阈值及定时任务失败均发送给运营者；只通过私有配置提供收件信息。 |
| 部署 | 公司现有服务器上的 Docker Compose，静态前端、API、定时任务接入现有反向代理及共享 `infra_mysql`、`infra_redis` | 与 Acuven 既有部署方式一致；本项目不启动数据库容器。部署镜像固定到提交版本，健康检查报告当前提交，凭据通过 GitHub secrets 与服务器私有配置注入。 |

检查边界：Worker 的 MXC 沙箱仅登记无需网络、数据库、缓存、Git 或环境变量的 Python 纯逻辑单测与 lint；Node 检查（TypeScript、ESLint、Vitest、构建）只放 CI。需要数据库或短信服务的集成测试也只在 CI 的隔离服务或模拟适配器中运行，绝不调用真实短信发送。

前端页面设计安排：第 3 步的最小骨架与 CI 可先做，不等待线框。实现用户可见页面前，Claude Code 提交页面结构、移动端与桌面端线框、三语文案及演示提示供 Kelvin 审阅。页面至少包含首页、商品列表与详情、购物车、结账、模拟支付结果、订单查询/确认收货/退款、注册登录与会员中心、管理后台（含店铺装修）、隐私说明。线框之后另出视觉稿（设计系统与 10 款主题、按页面排的画板）经 Kelvin 审阅；认可后把设计变量与每页参考图导出进仓库，页面实现以仓库内的导出为准。视觉稿变更若触及金额或个人资料的展示与操作边界，须复核 `docs/DESIGN.md` 的设计闸门。
