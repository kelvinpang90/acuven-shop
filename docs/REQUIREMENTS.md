# Acuven Shop 需求说明

> 文档版本：1.5 技术栈候批稿（2026-09-29）。1.0 的产品范围与上线标准已获批准；Kelvin 随后确定初期短信国家、收货资料不加密及使用共享 MySQL/Redis。共享备份的残留期与其余技术栈仍待批准，见 `docs/DESIGN.md` 1.5。

## 身份与目标

- `project_id`：`acuven_shop`；`task_id_pattern`：`^SHOP-TASK-[0-9]{3}$`，已于 2026-09-29 确认。
- Acuven 品牌的公开网店演示站，面向有兴趣购买网店方案的潜在客户。目标是让访客亲自体验完整流程，之后自行通过 WhatsApp 联系 Acuven；不在站内收集销售线索。
- 以通用示例实物商品演示。所有商品、金额、库存、支付、运费、发货与退款均为演示，不发生真实交易或履约。页面及关键操作须持续、清楚地标注这一点。
- 预计初期每天几十名访客。首版支持英文、中文、马来文切换，默认英文；桌面与手机均可使用。

## 访客与会员流程

1. 浏览、搜索、按分类及属性筛选示例商品；选择颜色、尺寸等规格与数量，加入购物车。
2. 允许游客填写自由文本收货人、电话及全球收货地址并下单；也可注册会员。演示站允许填写虚构资料，在表单附近告知不真实扣款或发货、资料仅用于演示且收货资料 30 天后匿名化；不设单独确认勾选框。
3. 结账展示 MYR 商品小计、优惠券与积分抵扣、示例运费、MYR 合计；不单列税费。按国家配置示例运费，马来西亚按州属细分，未单独配置的国家使用统一“其他国家”运费。按固定演示汇率显示访客国家货币参考金额，并标明仅供参考。
4. 模拟支付仅选择支付方式并点击成功或失败，不输入银行卡资料、不接真实支付服务。失败可重试且不重复下单。
5. 管理者在后台推进模拟发货；访客以订单号及下单电话查询订单，查看完整收货资料，并在查询页确认收货。该查询方式不使用短信验证码；安全限制及剩余风险见设计文档。
6. 访客可在模拟支付成功后 30 天内申请整单或部分商品退款，模拟发货及确认收货后仍可申请。只选择商品和数量，由系统计算金额；示例运费不退。管理员审核批准或拒绝，绝不发生真实退款。

## 会员、优惠与积分

- 会员使用国际手机号格式注册，注册与忘记密码时发送真实短信验证码；初期仅向马来西亚和新加坡手机号发送，其他地区仍可游客下单。注册后使用手机号加密码登录。手机号归属账号直至用户主动注销。
- 注册会员可在“我的订单”查看历史订单、积分及优惠券。手机号注册后自动认领该号码最近 30 天、尚未匿名化的游客订单；匿名化后的订单不自动认领。
- 只有会员可使用优惠券与积分。管理员可创建、停用固定金额或百分比优惠券，并设置有效期、最低消费及使用次数上限；优惠券和积分可叠加。
- 演示积分按实际支付的商品金额每 RM1 获 1 积分，100 积分抵 RM1；取得后 12 个月到期。游客结账提示无积分并引导注册。积分规则与退款后的回收见设计文档；货币最小单位称仙（sen），不与积分混用。

## 管理后台

- 首版一个管理员账号。可维护商品、图片、分类、规格、规格库存、价格、优惠券、运费区与演示汇率；可查看订单原始收货资料、推进发货状态、审核退款。
- 每天自动将示例库存恢复到管理员设置的初始值，历史订单、退款与积分继续保留。管理员可查看库存重置结果。
- 后台与前台均支持英文、中文、马来文。

## 明确不做

- 不做多商家入驻、真实收款、真实物流下单、真实退款或税费计算。
- 此前“不做跨境”已被 Kelvin 后续决定覆盖：首版须演示全球收货地址、全球示例运费与参考币种。此冲突已按较新决定解决；旧范围不得继续作为实现依据。
- 不提供真实银行卡输入；不以站内联系表单替代 WhatsApp 联系入口。

## 上线验收标准（原 1.0 已批准；备份残留条款修订候批）

- 三种语言及桌面、手机上，访客能完成搜索筛选、规格选择、游客下单、模拟支付失败重试与成功、订单查询、确认收货及退款申请；界面明确显示演示性质。
- 管理员能维护带图片与规格库存的商品、优惠券与全球运费规则，处理发货及部分退款；每日库存重置不改动历史订单或积分。
- 马来西亚和新加坡会员能用真实短信完成注册、密码重设和登录；白名单外或无法送达短信时明确提示并保留游客下单能力。短信服务账号开通、两国实际覆盖、费用与限流是上线依赖，不能在未验证时宣称可送达。
- 重复提交不产生重复订单、重复支付或重复退款；价格、优惠、积分、运费及库存由服务端计算，并有并发与失败重试测试。
- 原始收货资料在在线系统第 30 天删除，订单记录继续保留；共享 MySQL 的 binlog 残留期为当前 binlog 文件的轮换间隔 + 3 天，轮换间隔待运营者核实。整实例备份的实际保留天数 N 也待核实；原文最迟第 30 + max(binlog 残留期, N) 天才从这些副本中消失，核实前没有确定的天数上限。该延长的残留期须 Kelvin 随最终设计明确批准。验收还要核实轮换间隔、N、共享备份确实到期清理，以及管理员权限、账号注销、短信限流和匿名化失败告警。
- 关键流程通过 CI 与人工浏览器验收。对外发布前填入 WhatsApp 联系方式及短信服务凭据，均通过配置提供，不写入仓库。

## 技术栈与理由

建议方案，待 Kelvin 确认：

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 前端 | TypeScript、React、Vite；三语字典与响应式页面 | `ai_billing_hub`、`rs-roof-pms` 已使用该组合，适合商品列表、购物车、会员与后台交互。Vite 产物为静态文件，可由现有反向代理服务。 |
| 后端 | Python、FastAPI、Pydantic、SQLAlchemy、Alembic | 上述 Acuven 项目已有经验；用单个后端统一处理订单事务、认证、金额、积分及个人资料，避免把规则放在浏览器。 |
| 数据库 | 共享 `infra_mysql` 中的本项目独立库，使用 InnoDB 事务；数据库账号只授权本库 | Kelvin 已决定沿用 Acuven 惯例，演示站用户少，无须单独数据库容器。订单、库存、优惠与积分依赖事务及约束；共享备份残留见下文。 |
| 定时任务 | 与 API 共用 Python 业务代码的独立后台进程 | 负责每日示例库存重置、30 天匿名化、积分到期及超时订单清理；任务可重复运行、失败向运营告警邮件报告。初期不用 Celery。 |
| 图片 | 私有持久卷存原图与处理后的展示图，由后端校验与管理 | 初期每日几十访客，先复用单机 Docker 部署，不增加对象存储账号；须纳入备份并限制格式、大小与访问。 |
| 短信 | 推荐 Twilio Verify，后端保留短信服务接口；备选 Twilio Programmable Messaging + 自建验证码，待 Kelvin 选择 | Verify 托管验证码生命周期并提供防欺诈能力，减少自行维护的认证逻辑；Messaging 对短信内容控制更细，但验证码存储、重试和防刷都由本项目负责。两者均有覆盖、地区限制和费用，不能保证全球送达。 |
| 限流与人机验证 | 共享 `infra_redis` 分配给本项目的独立库编号保存短时计数；短信发送前验证人机挑战 | 多 API 进程共用计数。Redis 数据丢失时短时计数清零可接受；短信每日总量和费用预算另由本项目 MySQL 按日记录兜底，Redis 或 MySQL 不可用时停发短信。短信目的地白名单初期为马来西亚和新加坡，实际送达仍需运营验证。 |
| 备份 | 共享实例每天以 `mysqldump --all-databases` 备份全库；备份实际保留 N 天待运营者核实；binlog 残留期为当前文件轮换间隔 + 3 天，轮换间隔待核实 | 收货资料不加密，无法排除本项目表；在线第 30 天删除后，原文仍可在这些副本中留至第 30 + max(binlog 残留期, N) 天。上线前必须核实轮换间隔、N、共享备份会按期清理，并由 Kelvin 接受延长的残留期。运营者可选择在 `vps_infra` 每天定时执行 `FLUSH BINARY LOGS`，使 binlog 残留期约为 3 天；本项目只记录此依赖。 |
| 告警 | 运营告警邮件 | 匿名化、备份边界、短信费用阈值及定时任务失败均发送给运营者；只通过私有配置提供收件信息。 |
| 部署 | 公司现有服务器上的 Docker Compose，静态前端、API、定时任务接入现有反向代理及共享 `infra_mysql`、`infra_redis` | 与 Acuven 既有部署方式一致；本项目不启动数据库容器。部署镜像固定到提交版本，健康检查报告当前提交，凭据通过 GitHub secrets 与服务器私有配置注入。 |

检查边界：Worker 的 MXC 沙箱仅登记无需网络、数据库、缓存、Git 或环境变量的 Python 纯逻辑单测与 lint；Node 检查（TypeScript、ESLint、Vitest、构建）只放 CI。需要数据库或短信服务的集成测试也只在 CI 的隔离服务或模拟适配器中运行，绝不调用真实短信发送。

前端页面设计安排：第 3 步的最小骨架与 CI 可先做，不等待线框。实现用户可见页面前，Claude Code 提交页面结构、移动端与桌面端线框、三语文案及演示提示供 Kelvin 审阅。页面至少包含首页、商品列表与详情、购物车、结账、模拟支付结果、订单查询/确认收货/退款、注册登录与会员中心、管理后台、隐私说明。视觉稿变更若触及金额或个人资料的展示与操作边界，须复核 `docs/DESIGN.md` 的设计闸门。
