# Acuven Shop 演示交易与个人数据设计

> 文档版本：1.0 候批稿（2026-09-29）。本文件整体受设计闸门约束，Kelvin 批准此版本前不得实现涉及金额、订单、库存、状态、积分、优惠券、短信账号或个人数据的代码。

## 边界与原则

- 金额以 MYR 最小货币单位整数运算；其他货币只按管理员配置的固定演示汇率显示参考数，不参与结算。页面、订单与后台明确标为演示；无真实收款、退款、寄送、税费或银行卡输入。
- 公开访客可填真实或虚构收货资料。仅收集姓名、电话、国家、地区、地址及邮编等完成演示所需字段，不要求邮箱或证件。收货资料原文只保留 30 天；订单、商品和状态历史永久保留但须匿名化。会员手机号保留至主动注销。
- 全球短信注册以服务商实际覆盖范围为准；无法送达时不声称注册成功，允许继续游客下单。真实短信会产生外部费用。

## 数据模型

| 对象 | 字段与关键约束 |
| --- | --- |
| `Product` / `Variant` | 商品、分类、三语文案、图片引用、规格属性、MYR 单价、启用状态；每个规格有 SKU、管理员设定的每日初始库存及当日可用库存。价格与数量不得为负。 |
| `ShippingRate` / `DemoFxRate` | 国家运费、马来西亚州属运费、“其他国家”兜底运费；参考币种固定汇率及版本。下单存计算规则版本与金额快照。 |
| `Coupon` / `CouponUse` | 固定金额或百分比、有效期、最低商品消费、总使用上限、每会员使用上限、启停状态；使用记录与订单关联。 |
| `Member` / `OtpChallenge` | E.164 格式手机号、密码哈希、账号状态；一次性短信验证码只存哈希、到期时间、尝试计数，不存明文。 |
| `Cart` | 浏览器中的商品规格与数量；不信任浏览器价格，结账时服务端重算。 |
| `Order` / `OrderItem` | 不可猜测的订单号、可选会员 ID、状态、MYR 价格/优惠/积分/运费/应付快照、幂等键、创建与支付时间；商品名称、规格、数量和单价保留快照。收货资料加密存放于可独立匿名化的记录，订单只留引用。 |
| `PaymentAttempt` / `OrderEvent` | 模拟支付选择与结果、状态变更、操作者类别、时间、幂等键；事件不写收货资料原文。 |
| `RefundRequest` / `RefundLine` | 申请状态、每个商品规格的申请数量、按原订单快照计算的可退商品金额、审核人及理由；每件商品累计批准退款数量不可超过购买数量。 |
| `PointLedger` | 获得、抵扣、到期、退款追回、待抵扣积分的不可覆盖流水；每笔关联订单或退款，余额不得小于零。 |
| `AdminAccount` / `AuditEvent` | 单一管理员、密码哈希、会话及后台操作记录；图片只存引用与必要元数据。 |

## 计价、优惠、积分与库存

1. 服务端以订单规格价格快照计算商品小计；优惠券先抵商品额，积分再抵剩余商品额，二者均不抵运费，最终应付不得低于运费。满减、百分比、积分及汇率都使用明确舍入规则，展示与存储一致。优惠券仅会员可用，使用额度在下单时预占，取消或支付超时释放。
2. 积分按模拟支付成功后实际应付的商品金额，每完整 RM1 获 1 分；100 分抵 RM1。积分以批次记录 12 个月到期，先到期先使用；结账抵扣时预占，失败或取消时释放。游客不积累积分，提示注册。会员可认领手机号相同且尚未匿名化的近 30 天游客订单；为避免套利，认领不追发已完成的游客订单积分。
3. 管理员设置每个 SKU 的每日初始库存。下单事务预留当日可用库存，支付成功消耗预留，失败重试期间保持预留，15 分钟未支付自动取消并释放。每天按马来西亚时间重建当日可用库存为“初始库存减去仍有效的预留”，记录重置事件；历史订单不变。模拟退款不回补库存，避免跨日重复增加。
4. 商品、优惠、运费、汇率或积分规则的后台修改只影响新订单，已有订单及退款按快照计算。图片上传限制文件类型、大小并隔离存储，不能当可执行文件使用。

## 订单与退款状态

- 下单：`awaiting_demo_payment`；模拟支付失败仍停在此状态并记录失败尝试；成功进入 `demo_paid`。
- 管理员依次推进 `demo_paid` → `demo_packed` → `demo_shipped`；访客在查单页确认收货后进入 `demo_completed`。无真实物流单。
- 待支付订单可取消或超时为 `demo_cancelled`，释放库存、券及积分预占；已模拟支付订单不走取消，走退款流程。
- 支付成功后 30 天内可申请退款，包含已发货和已完成订单。退款与履约状态分开存储；`requested` → 管理员 `approved` 或 `rejected`。重复申请同一可退数量被拒绝；部分退款后余量仍可再次申请，总批准数量不超过购买数量。访客只选商品与数量，金额按原单每件实际支付商品额计算，示例运费始终不退；系统显示累计已退及剩余可退金额。
- 批准模拟退款时，按原计价分摊回退已抵扣积分，并追回该商品产生的积分。积分余额不足时扣至 0，剩余记待抵扣积分，以后获得积分先偿还；不出现负余额。已使用的券不恢复使用次数，避免重复领取优惠。所有退款均明确写“模拟”，无真实资金流。
- 所有状态迁移校验当前状态、操作者与数量；事务内写订单、流水和事件。已批准的退款不可再次批准，已完成的履约状态不可倒退。

## 失败、并发与重试

- 下单、模拟支付、确认收货及退款申请/审核均使用幂等键和数据库唯一约束。相同键相同请求返回原结果；同键不同内容报冲突。库存预占、券/积分预占及订单创建在同一事务，失败全部回滚。
- 网络中断时先查询原订单或申请状态，再允许重试；不以页面重试次数推断操作成功。短信发送失败不创建已验证账号，提示游客继续体验。
- 短信验证码短时有效、一次性使用；按手机号、来源及全站限制发送和校验频率，限制每日总量并在超过预算阈值时停发告警。不得把验证码、短信凭据或完整手机号写进日志。短信服务覆盖不足视为上线限制，展示明确错误。
- 每日库存重置、30 天匿名化、积分过期均可重复运行，使用操作标识保证只生效一次；失败有告警与人工补跑办法。

## 权限与资料保护

- 游客无需账号下单。订单查询使用高熵、不可枚举的订单号加下单电话原文比对；成功后按 Kelvin 的决定可见完整姓名和地址，不再要求短信验证。查询接口严格限流、防批量枚举、不缓存敏感响应，订单号不出现在公共索引或分析事件。此机制仍有剩余风险：知道订单号和电话的人可读取完整地址；上线前由 Kelvin 在本设计批准时明确接受。
- 会员注册通过真实短信验证手机号，之后凭手机号和密码登录；密码重设再次短信验证。密码安全哈希、会话到期、退出与服务端授权检查。账号注销须撤销会话、删除手机号与密码，并解除其订单关联；订单记录继续按保留规则存在。
- 仅管理员可见所有订单原始资料、维护商品/运费/优惠、推进发货和审核退款。访客仅能访问已通过查询验证的订单；会员仅能访问自己认领或下单的订单。后台单一管理员也须认证，不把权限检查留给前端。
- 收货资料加密存储，访问和后台导出受控并留审计记录；应用日志与监控不记录姓名、完整电话、地址、验证码、密码、订单查询参数。对外告知不会实际扣款或发货、资料用途与匿名化时间；无单独勾选框。

## 保留与匿名化

- 已模拟支付订单从支付成功起 30 天、未支付订单从创建起 30 天，自动删除该单收货姓名、电话、地址、邮编原文及可逆映射；订单商品、金额、状态、退款与积分流水继续保存，不能再凭电话查询或认领。已登录会员仍可见匿名化后的订单摘要。管理员不得从历史事件或图片中恢复收货资料。
- 会员手机号及密码哈希保留至主动注销。短信挑战和发送记录仅短期保留用于防滥用；日志最长 30 天。备份也不得让原始资料超过上述 30 天可恢复：采用按单独立加密密钥并到期销毁，或同等可验证的清除机制。匿名化任务失败必须告警，不能静默超期。
- 对订单展示需求不构成永久保留个人资料的理由；若改变用途、字段、访问方式或保留期，本设计批准失效，须重审。

## 上线依赖与设计闸门

- 运营者开通覆盖目标国家的短信服务，配置凭据、发送上限与费用告警；配置 WhatsApp 联系方式。仓库只记录变量名，不存真实号码、主机、密钥或服务凭据。
- Kelvin 批准 `docs/REQUIREMENTS.md` 1.0 与本文件 1.0 后，第 1 步闸门才通过。后续任一涉及金额或个人数据的设计变更均需重新批准对应版本。
