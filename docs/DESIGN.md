# Acuven Shop 演示交易与个人数据设计

> 文档版本：1.4 候批稿（2026-09-29）。1.0 的批准已因后续改动失效；Kelvin 已单独决定初期短信国家、收货资料不加密及使用共享 MySQL/Redis。备份残留期等规则仍待批准，1.4 整体获批前不得按本版实现受闸门约束的代码。

## 边界与原则

- 金额以 MYR 的仙（sen）为整数单位运算；积分数量一律称「积分」，不把仙与积分混称。其他货币只按管理员配置的固定演示汇率显示参考数，不参与结算。页面、订单与后台明确标为演示；无真实收款、退款、寄送、税费或银行卡输入。
- 公开访客可填真实或虚构收货资料。仅收集姓名、电话、国家、地区、地址及邮编等完成演示所需字段，不要求邮箱或证件。收货资料原文只保留 30 天；订单、商品和状态历史永久保留但须匿名化。会员手机号保留至主动注销。
- 初期短信注册只开放马来西亚和新加坡，且以服务商实际送达能力为准；白名单外或无法送达时不声称注册成功，允许继续游客下单。真实短信会产生外部费用。
- 「访客国家货币」按收货国家决定，不按 IP；该国无演示汇率时只显示 MYR，不猜测或临时请求实时汇率。

## 数据模型

| 对象 | 字段与关键约束 |
| --- | --- |
| `Product` / `Variant` | 商品、分类、三语文案、图片引用、规格属性、MYR 单价、启用状态；每个规格有 SKU、管理员设定的每日初始库存及当日可用库存。价格与数量不得为负；文案缺少当前语言时回退英文，再缺失则商品不发布。 |
| `ShippingRate` / `DemoFxRate` | 国家运费、马来西亚州属运费、“其他国家”兜底运费；参考币种固定汇率及版本。下单存计算规则版本与金额快照。 |
| `Coupon` / `CouponUse` | 固定金额或百分比、有效期、最低商品消费、总使用上限、每会员使用上限、启停状态；使用记录与订单关联。 |
| `Member` / `VerificationAttempt` | E.164 格式手机号、密码哈希、账号状态；推荐 Twilio Verify 托管验证码，只存提供方请求 ID、结果与限流元数据，不存验证码；此替换 **待确认**。备选 Programmable Messaging 时仍需 `OtpChallenge`（验证码哈希、到期与尝试数）。 |
| `Cart` | 浏览器中的商品规格与数量；不信任浏览器价格，结账时服务端重算。 |
| `Order` / `OrderItem` | 不可猜测的订单号、可选会员 ID、状态、MYR 价格/优惠/积分/运费/应付快照、幂等键、创建与支付时间；商品名称、规格、数量、单价，以及逐件优惠、积分、现金实付、获得积分的分摊快照。订单摘要不依赖收货资料记录存在。 |
| `OrderRecipient` | 收货姓名、规范化 E.164 电话、地址、邮编等原文，引用所属订单并为电话建立查询索引；到期删除整条记录。收货资料不做应用层加密。 |
| `PaymentAttempt` / `OrderEvent` | 模拟支付选择与结果、状态变更、操作者类别、时间、幂等键；事件不写收货资料原文。 |
| `RefundRequest` / `RefundLine` | 申请状态、每个商品规格的申请数量、按原订单快照计算的可退商品金额、审核人及理由；每件商品累计批准退款数量不可超过购买数量。 |
| `PointLedger` | 获得、抵扣、到期、退款追回、待抵扣积分的不可覆盖流水；每笔关联订单或退款，余额不得小于零。 |
| `CouponPhoneUse` | 推荐保留每张券关联的电话 HMAC 及已用次数至该券到期，以防注销重注册绕过次数；这属于可关联资料，**待确认**。它不用于查单，也不是对收货资料加密。 |
| `AdminAccount` / `AuditEvent` | 单一管理员、密码哈希、会话及后台操作记录；图片只存引用与必要元数据。 |

## 计价、优惠、积分与库存

1. 服务端以订单规格价格快照计算商品小计；优惠券先抵商品额，积分再抵剩余商品额，二者均不抵运费，最终应付不得低于运费。优惠券仅会员可用，使用额度在下单时预占，取消或支付超时释放。
2. **逐件分摊（推荐，待确认）**：先将商品按稳定的订单行序与件序展开。百分比券对整单商品小计计算一次，以十进制定点数按“四舍五入，恰好半仙进一仙”得到整仙折扣；固定金额券取券额与商品小计较小者。将整单券折扣按每件原价占商品小计的比例分摊；再将积分抵扣按每件券后金额占整单券后金额的比例分摊。每次分摊先向下取整到仙，余下的仙依小数余数从大到小补 1 仙，平手按订单行序、件序。分母为零时抵扣为零。每件现金实付 = 原价 − 分摊券额 − 分摊积分额；运费另计。整单及逐件分摊快照不可因后来改价而重算。
3. **获得积分（推荐，待确认）**：模拟支付成功后，先对整单商品现金实付合计每满 100 仙（RM1）给 1 积分，再按逐件现金实付比例用同一“最大余数、稳定序”算法分摊获得积分；不按行分别取整。100 积分抵 RM1。积分批次在取得后 12 个月到期，先到期先使用；结账抵扣时预占，失败或取消时释放。游客不积累积分，提示注册；认领过去游客订单不追发积分。
4. **分摊算例**：A 商品 2 件、各 RM10；B 商品 1 件、RM5。整单 10% 券减 RM2.50，分摊到 A 每件 RM1、B RM0.50；使用 300 积分抵 RM3，分摊到 A 每件 RM1.20、B RM0.60。三件现金实付依次 RM7.80、RM7.80、RM3.90，共 RM19.50，整单获得 19 积分，按稳定序分给 8、7、4。仅退第一件 A 时，模拟退现金 RM7.80，返还原抵扣的 120 积分，并追回该件获得的 8 积分；券不退、示例运费不退。这里的“每件实际支付商品额”**只指现金实付，不含积分抵扣**。
5. 退款批准时按原逐件快照返还抵扣积分并追回获得积分；积分余额不足时扣至 0，缺口记待抵扣。原抵扣积分批次若已经过期，**推荐待确认**：返还等量积分并给新返还批次 30 天有效期；备选为不返还已过期积分。任何次数的部分退款满足：累计模拟退现金 ≤ 该单商品现金实付合计；累计返还抵扣积分 ≤ 该单实际抵扣积分；累计追回获得积分 ≤ 该单实际获得积分。
6. 管理员设置每个 SKU 的每日初始库存。下单事务预留当日可用库存，支付成功消耗预留，失败重试期间保持预留，15 分钟未支付自动取消并释放。每天按马来西亚时间重建当日可用库存为“初始库存减去仍有效的预留”，记录重置事件；历史订单不变。模拟退款不回补库存，避免跨日重复增加。管理员当天修改初始库存仅从次日重置生效；当天可用库存不回写，需单独执行当日库存调整。
7. 商品、优惠、运费、汇率或积分规则的后台修改只影响新订单，已有订单及退款按快照计算。图片上传限制文件类型、大小并隔离存储，不能当可执行文件使用。

## 订单与退款状态

- 下单：`awaiting_demo_payment`；模拟支付失败仍停在此状态并记录失败尝试；成功进入 `demo_paid`。
- 管理员依次推进 `demo_paid` → `demo_packed` → `demo_shipped`；访客在查单页确认收货后进入 `demo_completed`。无真实物流单。**推荐待确认**：若访客不操作，模拟发货满 7 天自动确认收货；备选为仅在第 30 天匿名化前自动完成。自动完成只改演示状态，不影响 30 天退款期。
- 待支付订单可取消或超时为 `demo_cancelled`，释放库存、券及积分预占；已模拟支付订单不走取消，走退款流程。
- 支付成功后 30 天内可申请退款，包含已发货和已完成订单。退款与履约状态分开存储；`requested` → 管理员 `approved` 或 `rejected`。重复申请同一可退数量被拒绝；部分退款后余量仍可再次申请，总批准数量不超过购买数量。访客只选商品与数量，金额按原单逐件现金实付快照计算，示例运费始终不退；系统显示累计已退及剩余可退金额。**推荐待确认**：所有购买件数均已批准退款时，冻结后续打包/发货/确认收货的推进，保留退款前履约状态；备选为允许原流程继续并标明“已全额模拟退款”。
- 批准模拟退款时，按原计价分摊回退已抵扣积分，并追回该商品产生的积分。积分余额不足时扣至 0，剩余记待抵扣积分，以后获得积分先偿还；不出现负余额。已使用的券不恢复使用次数，避免重复领取优惠。所有退款均明确写“模拟”，无真实资金流。
- 所有状态迁移校验当前状态、操作者与数量；事务内写订单、流水和事件。已批准的退款不可再次批准，已完成的履约状态不可倒退。

## 失败、并发与重试

- 下单、模拟支付、确认收货及退款申请/审核均使用幂等键和数据库唯一约束。相同键相同请求返回原结果；同键不同内容报冲突。库存预占、券/积分预占及订单创建在同一事务，失败全部回滚。
- 网络中断时先查询原订单或申请状态，再允许重试；不以页面重试次数推断操作成功。短信发送失败不创建已验证账号，提示游客继续体验。
- **短信方案待确认**：推荐 Twilio Verify，由提供方负责验证码生命周期及防欺诈；系统只存验证请求与结果，不存验证码。备选 Programmable Messaging + 自建 `OtpChallenge`，需自行保证一次性、短有效期、尝试数及防刷规则。两方案均在发送前通过人机验证：推荐托管挑战并由后端核验令牌，备选自托管挑战，**待确认**。按规范化手机号、来源、国家及全站限流，超过每日总量或费用阈值停发并向运营告警邮件报告。短时限流计数存共享 `infra_redis` 为本项目分配的独立库编号，多 API 进程共用；Redis 数据丢失后这些计数清零可接受。**短信每日总量及费用预算另在本项目 MySQL 库以按日原子计数和预算记录兜底**：发送前按目的地预占保守的单次最高费用，未知费用时停发；结算后更新记录，防 Redis 重置后超过日上限。Redis 或 MySQL 不可用时短信停发。查单和管理员登录等依赖 Redis 限流的敏感接口也拒绝请求，商品浏览继续可用。不得把验证码、短信凭据或完整手机号写进日志。短信服务覆盖不足时展示明确错误。
- **初期短信国家（Kelvin 已确定）**：目的地白名单仅含马来西亚和新加坡；两国均须先验证服务商覆盖及运营权限，未通过验证的号码明确提示暂不可注册。其他国家仍可游客下单；以后扩展白名单须另行变更设计并批准。
- 每日库存重置、30 天匿名化、积分过期均可重复运行，使用操作标识保证只生效一次；失败有告警与人工补跑办法。

## 权限与资料保护

- 游客无需账号下单。下单时以收货国家作为默认区号解析自由文本电话；访客明确输入 `+` 国家码时以该号码为准。只检查区号和长度等格式是否可能成立，不校验号码真实存在，以允许虚构演示资料；格式不成立则提示修改、不创建订单。注册、查单和订单认领都用相同的 E.164 规范化结果。查单先按高熵订单号定位，再与该单 `OrderRecipient` 的规范化号码比对；认领只查近 30 天、尚未匿名化且未认领的游客订单。收货资料已存原文，原先的逐单 HMAC 盲索引不再提供额外保护，故删除该设计。查询成功后按 Kelvin 的决定可见完整姓名和地址，不再要求短信验证。查询接口严格限流、防批量枚举、不缓存敏感响应，订单号不出现在公共索引或分析事件。剩余风险仍是知道订单号和电话的人可读取完整地址。
- 会员注册通过真实短信验证手机号，之后凭手机号和密码登录；密码重设再次短信验证。密码安全哈希、会话到期、退出与服务端授权检查。账号注销须撤销会话、删除手机号与密码、解除订单关联；积分余额与未用券作废，积分和券使用流水保留去标识化审计记录。每个游客订单只能认领一次，注销后同号重注册不得再次认领或补发积分。**推荐待确认**：为防每会员用券上限被注销重注册绕过，保留手机号 HMAC 的每券使用计数至券到期，之后删除；备选注销时删除该索引并接受次数上限可被绕过。推荐项的 HMAC 仍属于可关联数据，须在隐私告知中列明。
- 管理员登录按来源与账号组合限流，连续失败后短时锁定并告警；锁定解除不绕过密码校验。单一管理员也须服务端授权与会话到期。
- 仅管理员可见所有订单原始资料、维护商品/运费/优惠、推进发货和审核退款。访客仅能访问已通过查询验证的订单；会员仅能访问自己认领或下单的订单。后台单一管理员也须认证，不把权限检查留给前端。
- 按 Kelvin 的新决定，收货资料不加密存储；访问和后台导出仍受服务端权限控制并留审计记录，数据库账号与其他项目隔离。应用日志与监控不记录姓名、完整电话、地址、验证码、密码、订单查询参数。对外告知不会实际扣款或发货、资料用途与匿名化时间；无单独勾选框。

## 保留与匿名化

- **在线删除与共享备份残留（待 Kelvin 接受）**：已模拟支付订单从支付成功起 30 天、未支付订单从创建起 30 天，自动删除在线 `OrderRecipient` 原文；订单商品、金额、状态、退款与积分流水继续保存，在线系统不再凭电话查询或认领。已登录会员仍可见匿名化后的订单摘要。游客订单自动完成规则见上方候选项。
- 共享 `infra_mysql` 每天以 `mysqldump --all-databases` 备份整个实例，不能排除本项目收货资料表；二进制日志保留 3 天。共享备份的实际保留天数记为 **N，待运营者核实**，不假设为 7 天。在线第 30 天删除后，原文在二进制日志里最多残留 3 天，在共享备份里残留到相应备份到期；按现有保留规则，最迟第 **30 + max(3, N)** 天才从这些副本中消失。管理员也不得从在线历史事件或图片中恢复原文；不加密不保证物理介质取证级清除。
- 这比 1.0 批准的“30 天后匿名化且备份也不可恢复”目标更宽。Kelvin 须在批准本文件最终版时**明确接受共享备份残留期**；在运营者核实 N 和共享备份确实会到期清理之前，不得宣称残留期已有确定上限。
- 会员手机号及密码哈希保留至主动注销；推荐的用券防套利电话 HMAC 保留到对应优惠券到期，须单独告知。短信验证请求及发送记录短期保留用于防滥用；日志最长 30 天。匿名化失败或备份边界违规都向运营告警邮件报告，不能静默超期。
- 对订单展示需求不构成永久保留个人资料的理由；若改变用途、字段、访问方式或保留期，本设计批准失效，须重审。

## 上线依赖与设计闸门

- 运营者开通覆盖目标国家的短信服务，配置凭据、发送上限与费用告警；配置 WhatsApp 联系方式。仓库只记录变量名，不存真实号码、主机、密钥或服务凭据。
- `docs/DESIGN.md` 1.0 的批准因本版修改失效；Kelvin 选定所有「待确认」项并批准本文件的最终版本后，金额及个人数据设计闸门才重新通过。未来相关设计变更仍须重新批准。
